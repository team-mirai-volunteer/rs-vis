# 財政計算の Worker 化と政策別負荷の入力

モデル版 `2026-09-15.3`。インフラの適用は運用側が担当し、この変更はアプリケーションの改善を扱う。

## 操作と計算

- `client/lib/fiscal-space-engine.ts` にページの計算を集約し、`client/workers/fiscal-space.worker.ts` で実行する。推計・上限探索・監査・政策比較・生産関数比較・長期試算が対象。
- 入力は即座に更新する。160msの入力待ちと「実行中1件＋待機中の最新1件」で連続操作をまとめ、入力変更時点で古い結果を無効にする。
- 単独政策の上限は、金額以外の条件をキーに1組だけ保持する。比較表には未配分の政策も必要なため、候補政策自体は削除しない。
- 起動・通信失敗とモデルの計算範囲外を区別し、入力を維持して再試行できる。古い結果を表示する間はその旨を明記する。
- Reactコンポーネントから計算用の電源設定生成を分離し、WorkerからUIを読み込まない。

Workerは[Webpack公式の構文](https://webpack.js.org/guides/web-workers/)でバンドルする。
本番は既定のWebpackビルドで `worker-src 'self'` を使う。開発用Turbopackはblobの起動コードを生成するが、開発サーバーには従来どおりCSPを付与しない。
`NEXT_DIST_DIR` でローカル検証用の成果物を分離できる。Turbopackのrootもリポジトリに固定し、親ディレクトリのlockfileによる誤検出を避ける。

## 未入力と負荷ゼロ

人員、支出年ピーク電力、稼働後ピーク電力を独立したnullable値とする。
空欄は未評価、明示した0は負荷ゼロの仮定。入力を有効にするだけでは評価済みにしない。
産業は人員原単位、電力は支出年と稼働後の両原単位が既知かで判定する。
既知の部分だけですでに制約を超える場合は違反を表示し、不明部分によって隠さない。
政策比較表にも不明な負荷を併記する。

### 事業計画からの換算

同じ事業・同じ年0価格の公費額 `B` 兆円を分母にする。

| 入力 | 1兆円当たりの原単位 |
| --- | --- |
| 追加人年 `W`、当該産業の年間人員能力 `L` | `W / L / B` |
| 支出年の純追加ピーク `C` MW | `C / 1000 / B` GW |
| 稼働後の系統ピーク寄与 `O` MW | `O / 1000 / B` GW |
| 稼働後年間電力 `E` GWh、年間負荷率 `f`、系統ピークとの同時発生係数 `c` | `E / 8760 / f * c / B` GW |

直接の稼働後ピークが分かる場合はその値を優先し、年間電力量から重ねて加算しない。
年間電力量だけではピークを求めない。負荷率と同時発生係数が未入力なら未評価。
支出年の負荷は当年費用に比例、稼働後の負荷は支出年別に稼働遅れ・寿命・減耗を適用する。
名目政策費用は従来どおり年0価格へ換算して原単位に掛ける。

これは利用者が入力した事業条件の比例換算であり、日本の産業連関表による実証校正ではない。
人員比率は設備稼働率の代理指標で、他産業への波及や職種別の不一致は含まない。
年間電力量から燃料輸入費への接続は `simulate.ts` で実装済み。`policyLoads` が返す年ごとの追加電力量（GWh）を、火力限界比率 `marginalThermalShare`（既定1＝追加需要は全て火力で賄う仮定・変更可）× 燃料輸入単価 `fuelImportYenPerKwh` × 共通価格指数 × エネルギー価格ショックで円換算し、`importBill` に加えて既存の燃料経路（輸入・必需輸入・エネルギー価格圧力）へ流す。発電投資の燃料削減と同じ「政策固有の物理需要」として扱い、公表輸入反応からは控除しない（控除係数の根拠が無いため二重計上の可能性を注記で残す）。係数の無い政策は `null`＝未評価。既存の事業別輸入仮定に機械的に加算しない（設計は `docs/tasks/20260916_0038_財政余力モデル5指摘の検証と残課題設計.md` A項）。
公費と総事業費を混ぜないこと、既存設備の需要を除くことを入力画面に明記する。

## 終了年の比較

入力した年額・配分を固定して、期限のある政策の支出期間を1〜公表最終年で比較する。
恒久政策はそのまま。最終年GDPの政策なしとの差、判定用CPIのピークと年、期間内の累計政策費用を並べる。
評価には年0も含む。期間に応じて累計費用が変わるため、同額予算での政策比較とは説明しない。
政府支出1年限りの公表実験と、複数年支出を継続反応の変化分で近似する違いを表の直下に記載する。
公表期間を超えた乗数外挿は行わない。

## 共有と検証

共有URLには未入力状態と事業換算の元データを保存し、復元時も検証する。
旧版 `2026-09-15.2` の数値原単位を保持したURLも読み込める。
換算係数は元データから毎回生成するため、保存された古い派生値に依存しない。

- 単体：計算層との一致、転送可能性、上限キャッシュの更新、連続入力・通信失敗・再試行、独立した未評価、換算・二重加算防止・稼働年、URL互換性。
- ブラウザ：実Workerの起動、連続編集、空欄の判定、事業換算の共有と復元、起動失敗時の入力保持と再試行。
- Webpackの開発サーバーで `FISCAL_WORKER_CSP_SELF=1` を付けて同じWorkerテストを実行すると、ページに本番同様の `worker-src 'self'` を加えて検証できる。

これらは実装の整合性の検証であり、経済モデルの実証的妥当性を証明するものではない。
