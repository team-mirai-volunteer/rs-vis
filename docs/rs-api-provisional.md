# 2025年度執行実績の暫定取り込み

2026年度RSシートの公開APIから2025年度執行額・支出先・資金の流れを取得する。画面は `/budget-sankey?year=2025&b=initial&view=provisional`。右側の表示プリセットで「統合（暫定）」を選ぶ。左側のMOF予算基準（当初・補正など）とは独立して保持する。旧URLの `b=execution` は当初予算＋統合（暫定）へ読み替える。

表示時に、選択したMOF予算グラフと暫定支出を予算事業IDで接続する。予算側の金額・既存の辺は変えない。対応する予算事業がない支出には「予算未突合」の事業枠を置き、MOFからの辺は作らない。この枠の内部値0はレイアウト専用で、画面では0円予算として表示しない。予算金額の絞り込みからも除外する。

取得元は `https://rssystem.go.jp/api/projects/?sheet_type=RS&fiscal_year=2026&page=1&page_size=100` と、各UUIDの `payment-groups/`、`payment-edges/`。認証は不要。取得時点で一覧に載る事業のみであり、全事業の最終公表が完了したとはみなさない。

```
npm run fetch-rs-api-2026
npm run generate-rs-api-2026
```

取得は4並列・各要求後100ms待機・45秒タイムアウト・最大4回の試行。各応答を `data/rs-api/2026/` に保存し、再実行時は成功済みを再利用する。新しい公開内容に更新する場合は `node scripts/fetch-rs-api.mjs 2026 --refresh`。`--limit N` は支出先取得件数の上限（執行額の大きい順）、一覧は全件取得する。失敗・未取得を空配列や0円として補完しない。ページング中に一覧が変わった場合は件数・UUID重複チェックで停止する。

生成物（`.gz` をGit管理）:

- `unified-budget-2025-execution-graph.json`: 府省庁→事業（執行額）→事業（確認済み直接支出先への合計）→支出先。
- `rs-api-2026-details.json`: 事業概要・全支出ブロック・支出先・契約金額・費目使途・資金の流れ。専用APIが1事業ずつ返す。
- `rs-api-2026-provenance.json`: 公開件数・取得範囲、元URL・取得日時・応答JSONのSHA-256。生応答はローカルキャッシュに保存。

グラフは既存のprebuildの `unified-budget-*-graph.json.gz` 展開対象。詳細・取得記録はブラウザ用に展開せず、既存のサーバ用 `.gz` 同期対象となる。

## 金額と年度の扱い

APIの金額単位は円。表示サイトの千円を再度掛けない。`previous_year_execution_amount` はシート年度の前年度の執行額。`last_implemented_fiscal_year` は**外部有識者点検の最終実施年度**で、支出年度ではない。

支出先は前年度の記載（[令和8年度作成要領](https://www.gyoukaku.go.jp/review/R08sakuseiyouryou.pdf)）。未執行事業には想定支出先も入力されるため、正の執行額を確認できない事業から支出先への辺は作らない。金額がnull・負数・非公表分を含む場合は未確認とし、執行額不明の事業はグラフに描かず、詳細データには保持する。

直接支出は `is_connected_to_source_root` の辺を持つブロックの `type=payee` のみ。参考線・再委託・接続不明のブロック・国庫債務負担行為等の契約先を直接支出に混ぜない。全ブロックは詳細で確認できる。「その他」は事業・ブロック内に限定し、全国で一法人のように集約しない。

事業の執行額と支出先上位者の合計は別の値として保持する。統合表示の事業列には選択した予算基準の金額を残し、執行額は暫定詳細に表示する。丸め・記載範囲等による差を埋める架空の支出先は作らない。財務省の会計・項・目との接続は既存の2025年度予算グラフを利用する。2026年度シートによる新たな科目突合、国全体の決算・純計、政策評価・既存AI評価との接続は行っていない。

## CSV公開後の置換

APIキャッシュと公式CSV入力 `data/year_2026/` は別ディレクトリ。従来の2024・2025シート生成物、2025年度の当初・補正予算グラフは上書きしない。

1. `node scripts/download-rs-csv.mjs 2026` と `python scripts/extract-rs-csv.py 2026` で公式CSVを取得する。
2. 予算事業IDで突合し、事業数・2025年度執行額・ブロック別支出額・直接支出の判定をAPIスナップショットと比較する。API専用ID（UUID）を既存の数値IDの代わりに使わない。
3. CSVを入力とする変換を追加し、同じ事業ID・グラフ形式で再生成する。CSVの列構成確認と2026シートの詳細API対応を済ませてから、表示の暫定注記・専用詳細の接続を切り替える。API取得日時・件数のままCSVを正式版と表示しない。
4. 正式版の画面・件数検証後に暫定ファイルを退役する。単にファイル名だけを変更して旧年の評価・詳細に接続しない。

現時点では公式CSVの公開・列構成を未確認のため、置換そのものは実施していない。

既存サンキーの年度・基準切替・配信ファイル確認のE2E 4件も成功。prebuildで新規 `.gz` の配信・サーバ用同期を確認した。

ビュー位置修正後は、MOFの当初・補正の全ノード金額・既存の全辺・集計値を保持する変換テスト、予算未突合の扱い、左右選択と再読込・PC/スマホのE2E 3件を検証した。
