# バブルチャートビュー（/project-bubble）設計と埋め込みモデル選定

作成: 2026-07-27 10:52 JST

## 何を作るか

事業を「意味的に近いものが近くに並ぶ2次元マップ」上に配置し、
1事業=1バブルとして府省庁の色で塗り、大きさをAI評価などの指標で変える可視化。

参考: https://evidence2policy.vercel.app/

- **位置 (x, y)**: 事業説明文の埋め込み → UMAP で2次元に圧縮
- **色**: 所管府省庁
- **大きさ**: 切替式（正規化予算 / 継続年数 / 総合点の逆数＝低評価ほど大きい）
- **クラスタ**: 埋め込みの高次元空間で KMeans。ラベルを重心に表示

「総合点の逆数」を大きさに使うのが本質。**問題のある事業ほど画面上で目立つ**ようにして、
意味的に近い事業の塊の中で、どこに低評価が固まっているかを一目で見せる。

## 埋め込みモデルの選定（実測）

MTEB等の一般ベンチではなく、このデータで実測して決めた。
測定スクリプト: `scripts/benchmark-embedding-models.py`
結果: `tests/benchmark-results/embedding-model-selection-2025.json`

### 方法

- 母集団 5,788事業（本文80文字未満は除外）から policyCategory で層化サンプル 576件 / 32カテゴリ
- 入力テキスト = 事業名 + 目的 + 概要 + 現状の課題（1,200文字で打ち切り）
- 正解ラベルは既存の `policyCategory`（32分類）と `ministry`（31府省庁）
  - policyCategory は同じ本文からAIが付けたラベルなので完全な外部正解ではない。
    ただし「意味の近い事業が近傍に来るか」の代理としては機能する
- 指標
  - `knnAcc` / `knnMacroF1`: leave-one-out kNN(k=10, cosine)。局所的な近傍の質
  - `silhouette`: policyCategory をクラスタとみなしたシルエット係数
  - `kmeansAri` / `kmeansNmi`: KMeans(k=32) と policyCategory の一致度
  - `umapKnnAcc`: **UMAP 2次元に落とした後**の kNN 精度。本番の見え方に最も近い

### 測定時に踏んだ罠（再測定時の注意）

1. **短文での類似度テストは信用しない。** 選定前に5〜10語の短いフレーズで
   コサイン類似度を見たところ「農業の担い手育成 vs スマート農業(0.744)」より
   「農業の担い手育成 vs 巡視船建造(0.757)」の方が高いという逆転が出た。
   実文長（数百文字）では正常に効く。短文は判断材料にしない。
2. **UMAP後の2D座標にコサイン距離を使わない。** 初回の測定で UMAP 後の kNN が
   全モデル 0.17〜0.22 と不自然に低く出たが、これは2D座標を L2正規化してから
   内積を取っていたためで、原点からの角度しか見ていなかった。
   ユークリッド距離に直したら 0.42〜0.57 の妥当な値になった。

### 観察: マップは部分的に「府省庁の地図」になる

どのモデルでも府省庁の kNN 精度(0.733)が政策分野(0.620)を上回る。
事業説明文には所管庁ごとの書きぶりの癖が強く出ているため。

これは避けられないが、今回は府省庁で色を塗る設計なので、
位置と色が整合して読みやすくなる方向に働く。
逆に「同じ色の塊の中に紛れている異質な事業」や
「複数の色が混ざっている領域」が、分野横断・類似事業の重複を示す手がかりになる。

## データパイプライン

`scripts/generate-project-map.py --year 2025`

1. `rs{year}-project-details.json` から本文、`project-quality-scores-{year}.json` から
   ministry / policyCategory / スコアを読む
2. gemini-embedding-001 で埋め込み（テキストのSHA256でキャッシュ、再実行は無料）
3. UMAP(n_neighbors=15, min_dist=0.1, metric=cosine, seed固定) で2次元へ
4. 高次元側で KMeans。クラスタラベルは構成事業の TF-IDF 上位語 + 最頻 policyCategory から生成
5. `public/data/project-map-{year}.json` を出力（座標とクラスタIDのみの軽量ファイル）

出力を軽量に保つのが方針。ministry / budgetAmount / totalScore / yearsRunning は
すべて既存の `/api/quality-scores` が返すので、マップ側は pid・x・y・cluster だけ持ち、
クライアントで pid 結合する。重複を持たない。

## UI

`app/project-bubble/page.tsx`（`/sankey-svg`・`/quality` と同列の独立ページ）

- サンキー図と同じく**画面全体が図**。ツールバー（左上）・凡例/詳細（右上）・
  表ビュー（下からのシート）はすべてフロートで重ねる
- 5,794バブルの描画とズーム/パンのため **canvas** を使う（SVGだと再描画が重い）。
  当たり判定は画面座標に格子インデックスを張って「最も近い点」を引く方式。
  2pxの点にピンポイントで乗せる操作を要求しない
- 半径は**画面ピクセル固定**。ズームは点の間隔だけを広げ、密集を解くために使う
- **衝突回避配置**: UMAP座標をズーム1の画面座標に落とした後、円の重なりを格子スイープで
  反復緩和する（beeswarm方式）。ただし完全な非重畳を要求すると密集地帯で全体が
  押し広げられ一枚のハニカムになって構造が消えるため、
  (1) 中心距離は半径和の0.62倍まで許す（縁の重なりは残る）
  (2) 元位置からの移動量は22pxまで、の2つで「なるべく避ける」に留めている
- 年度切替タブは実装済み。座標が無い年度は API が 404 を返し、UI が生成コマンドを案内する
- ホバーでツールチップ、クリックで右パネルに詳細（支出先・サンキー図へのリンク付き）

### 色の扱い（重要な制約）

37府省庁を色だけで同定するのは原理的に不可能。dataviz の検証済みパレットを
バブル（全ペアが同時に画面に出る形）で使った場合、CVD安全を満たすのは**最大4色**だった
（`scripts/validate_palette.js` で8スロット中の全組み合わせを探索した結果、
両モードで通るのは blue/yellow/magenta/green の4つのみ）。
実測でも8色だと 緑↔橙 ΔE 3.2 (protan)、赤↔橙 ΔE 7.1 (normal) と閾値を下回る。

そこで役割を分けている:

- **色** = かたまりの手がかり。「事業数トップ10 ∪ 予算額トップ10」（12府省庁）に
  スロットを割り当て、残りはグレーへ畳む。9〜12色目は検証済み8色への追加スロット
  （シアン/ブラウン/オーキッド/オリーブ）で、精度はさらに下がるが手がかりとしては機能する
- **同定** = 凡例ホバー/クリックでの強調、ホバー時のツールチップ、表ビュー
- **省庁の勢力圏レイヤ** = 点の塗り分けとは独立に、府省庁が優勢な領域を背景に淡く塗る。
  データ空間の格子に各点をガウス核で撒き、セルごとの最多府省庁で塗る（優勢と言えない
  混在地帯は塗らない）。各府省庁のKDEピークに省庁名ラベルを置く。
  「色=推奨判断」にしたとき、どの省庁の縄張りに低評価が固まっているかを読むための層

凡例クリックでの強調は装飾ではなく、この二次符号化そのもの。外してはいけない。
色の割り当ては常に全件での順位で固定し、絞り込んでも生き残った系列の色が変わらないようにしている。

塗り分けは3通り: 府省庁（既定）/ 政策分野グループ（7分類・スロットに収まる）/
推奨判断（状態を表すので系列色ではなくステータス色。7段階を4色に畳むため文字を必ず添える）。

### バブルの大きさ

**順位（パーセンタイル）ベース**。半径 = MIN + span × rank^1.5。

最初は「対数 → 平方根で面積比例」で実装したが、金額は10^4〜10^13と10桁開いており、
対数に落としても大半の事業が中央の似た半径に潰れて大小が読めなかった。
順位ベースなら半径が分布全体に均等に広がり「他の事業より大きいか」がそのまま見た目になる。
指数1.5で分布の端（最上位）ほど強調する。スクリーニング用途なのでこれが正しい。
絶対量の比は犠牲になるため、目盛りに中央値・上位10%・最大の実値を添える
（例: 予算額なら 中央値2.9億円 / 上位10% 149.5億円 / 最大30.04兆円）。

既定は「総合点の逆数」。**問題のある事業ほど画面上で大きくなる**ようにするのがこのビューの主眼で、
意味的に近い事業の塊の中で、どこに低評価が固まっているかを見るためのもの。
スケールは常に全件で決める（絞り込むたびに同じ事業の大きさが変わると比較にならない）。

## 実装時に踏んだ罠

**Tailwind v3 は目盛りに無い不透明度を受け付けない。** `bg-white/97` と書いたところ
背景が完全に透明になり、ツールチップの文字がキャンバスに直接重なった。
v4 と違い v3 は `/97` を計算せず、テーマの opacity スケール
（0,5,10,20,25,30,40,50,60,70,75,80,90,95,100）に無い値は単に無視する。
`bg-white/[0.97]` と書くか、スケール上の値を使うこと。
`border-black/15` と `opacity-45` も同じ理由で効いていなかった。
