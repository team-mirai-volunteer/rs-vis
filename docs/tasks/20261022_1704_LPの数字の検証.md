# LP の数字の検証（再計算スクリプトとの突き合わせ）

## 依頼

LP（`/lp`）の数字の計算根拠をモーダルで見せる実装（コミット 86eea95）に続き、根拠メモの値をそのまま載せるのではなく、手元のデータから実際に再計算して検証する。

## やったこと

- `scripts/verify-lp-figures.ts`（`npm run verify-lp-figures`）を追加。`app/lp/insights.ts` の 16 カードと Hero の 4 統計に出てくる数字 60 項目を、`public/data` の生成物から各カードの basis と同じ定義で再計算し、載せている値と突き合わせる。不一致があれば終了コード 1。
- 手元の生 JSON（`project-quality-recipients-2025.json`）が 7 月の古いもので、`.gz`（8 月）より優先して読まれていた。`gunzip` で更新した（これで `tests/lp-content.test.ts` の事務局の検証も通るようになった）。このファイルは Vercel の都合で展開禁止なので、`scripts/decompress-data.sh` には「生 JSON が `.gz` より古ければ消す」処理を足した。
- 初回は 60 項目中 44 が一致。不一致 16 件を 1 つずつ調べ、原因ごとに直した。最終的に 60 項目すべて一致。

## 不一致の内訳と対応

| 項目 | 載せていた値 | 再計算 | 原因 | 対応 |
|------|-------------|--------|------|------|
| 国庫返納の額 | 4,000億円 | 4,042億円 | 丸め | 4,042億円に修正（4 か所） |
| 執行率50%未満の母数・件数 | 1,624 / 340 | 1,632 / 342 | 根拠メモの値がデータと合わない（原因不明。同じ条件で `rs2025-project-budget-history.json` の 2024 年度から数えても 1,632 / 342） | 図の数字を 342事業 に修正 |
| 3年以上執行率50%未満 | 30件 | 定義により 12〜60 | 根拠メモの「いずれかの年で予算100億円以上」では 60 になり、30 を再現できる定義が無い | 「予算現額100億円以上で執行率50%未満の年が3年以上」と定義し直して 38件 に修正。例示した事業（公立学校施設整備費・地域脱炭素移行・医療用物資・マイナンバー海外利用）はこの集合に含まれる |
| 全体の執行率 2023・2024 | 85.7 / 87.0 | 85.6 / 86.6（執行額未記載を除外） | 執行額が未記載の事業を 0 として合計すると 85.7 / 87.0 で一致 | 定義を basis とスクリプトに明記。値は変えない |
| 再委託3段以上の金額 | 17.1兆円 | 予算現額なら 7.6兆円 | 17.1兆円は支出先への支出合計（`spendTotal`） | 文言を「支出先への支出合計は17.1兆円」に修正 |
| 別財源の合流の金額 | 3.46兆円 | 予算現額なら 1.88兆円 | 3.46兆円は合流した別財源の額（`separateOriginAmount`） | 文言を「合流した金額は3.46兆円」に修正 |

| 落札率の記載がある契約数 | 12,188 | 12,190 | 応札0者の2件を含めていた | スクリプトを応札1者以上に限定 |
| 基金 1.40兆円、1者応札 48.0% / 93.0 | — | 1.4 / 48 / 93 | 表示桁の違い | スクリプトの整形を修正 |

## 分かったこと

- 図の大きい数字（figure）で変わったのは「340事業 → 342事業」の 1 つ。残りは本文（facts）と basis の文言・定義の修正。
- 根拠メモの集計スクリプトが残っていなかったため、「3年以上執行率50%未満 30件」「事務局 446件・3,949億円」「子育て上位10事業で実績2事業」の 3 つは元の定義を復元できなかった。今回は再現できる定義に置き換えて数字を直し、その定義を basis に書いた。
- 原資料から読んだ数字（広報の 64.8億円、租税特別措置の適用額）のうち、租特は `app/lib/tax-expenditures/data.json`（総括表の転記）から 8 項目を検算して一致。広報カードの PDF 由来の数字は検算対象外。

## 今後

- LP の数字を直したら `npm run verify-lp-figures` を回す（`app/lp/insights.ts` のヘッダーに記載）。
- データを更新したら同じスクリプトで差分が出る。差分が出た項目は basis の定義に沿って本文を直す。
