# サイドパネルの共通化方針（ビュー非依存の詳細パネル）

## 現状

- 共通なのは枠だけ（`client/components/SidePanelChrome.tsx`: 浮島カード・開閉タブ・幅リサイズ）。
- 中身（選択ノードの見出し・金額・バッジ・関連ノードのタブ・出典リンク）は **6 か所で別実装**:
  `app/sankey-svg/page.tsx`（インライン）、`app/subcontracts/[projectId]/page.tsx`、`mof-hierarchy/HierarchyChart.tsx`、
  `mof-kou-sankey/SankeyChart.tsx`、`mof-section-rs-sankey/SankeyChart.tsx`、`unified-budget/UnifiedSankeyChart.tsx`。
  さらに表ビュー側に `KouSidePanel` / `KouMokuSidePanel` / `BlockInspector` がある。
- どれも「サンキー図のノードをクリックした」前提で、選択状態・関連ノードの計算・パネル描画が各チャート部品の中に閉じている。
  統合ビューの検索下オフセット（`topOffset`）のように、ページ固有の都合を chrome 側に足す形になり始めている。

## 何が問題か

各ビューはいずれ統合ビューに寄っていく。そのとき残るのは「ノードを選ぶ → 詳細を見る → 関連へ移動する」という操作であって、
サンキーという描画方式ではない。パネルの中身がチャート部品の内側にあると、

- 見出し・バッジ・タブの見た目が 6 通りに揺れる（既に「選択を解除」ボタンや会計バッジの作りが違う）
- 表・バブル・ツリーなど別の描画に切り替えたときパネルを作り直すことになる
- 統合時に「どの実装を正にするか」の判断と移植が発生する

## 方針

**描画方式に依存しない `NodeDetailPanel` を 1 つ作り、各ビューは「選択ノードをこの形に写す」だけにする。**

```ts
interface NodeDetail {
  title: string;                       // ノード名
  amount: number;                      // 円
  amountLabel?: string;                // 当初予算 / 執行額 / 支出額 …（基準に連動）
  badges: { label: string; tone: 'column' | 'account' | 'kind' | 'neutral' }[];
  facts?: { key: string; value: string }[];           // 所管・項コード・出典 など
  links?: { label: string; href: string; external?: boolean }[];
  related: { label: string; items: RelatedItem[] }[]; // タブ: 所管(1) 項(150) 事業(903) …
  notes?: string[];                    // 「表示数の上限から溢れています」等
}
interface RelatedItem { id: string; name: string; amount: number; href?: string }
```

- `client/components/detail/NodeDetailPanel.tsx`（見出し・金額・バッジ・注記・facts・タブ付き関連一覧・閉じる）
- 選択・関連計算はチャートから出し、`useNodeSelection(graph)` 系のフックに寄せる（統合ビューの `focus.ts` が既に純関数なので流用できる）
- 各ビューは `toNodeDetail(node, graph, ctx)` を持つだけ。バッジの色はトークン、金額表記は `formatBudgetFromYen` に統一

## 進め方

1. 統合ビューで `NodeDetailPanel` を作って置き換える（今いちばん手が入っている場所。基準ラベル連動も入る）
2. `mof-hierarchy` / `mof-sankey` / `mof-kou/[id]` を同じ部品に載せ替える（構造がほぼ同じ）
3. `/subcontracts/[projectId]` と `/sankey-svg` は最後（独自要素が多い。`BlockInspector` は facts/related に写せる）
4. `SidePanelChrome` の `topOffset` は残すが、chrome にページ都合を足すのはここまでにする

## やらないこと

- 描画（サンキー本体）の共通化はここでは扱わない。`mof-sankey-layout` を 5 チャートが共有している現状で足りている
- URL 名 `/budget-sankey` の変更は別件（ナビ・サイトマップ・共有 URL に影響）
