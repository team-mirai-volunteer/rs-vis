## 新たな指摘

### 中 1. GITHUB_TOKEN で PR を作るにはリポジトリ設定が要る（`.github/workflows/budget-requests.yml`）

`gh pr create` を `GITHUB_TOKEN` で行うには、Settings → Actions → General の「Allow GitHub Actions to create and approve pull requests」が有効である必要がある。無効だと毎週 publish ステップで失敗する。API の権限不足でこちらから設定を確認できなかったので、マージ前に管理者が確認する。

### 中 2. 更新 PR に CI が走らない（`scripts/publish-budget-requests.ts` 末尾）

PR 本文にも書いてあるとおり、GITHUB_TOKEN が作った PR には `checks.yml`（pull_request トリガー）が走らない。publish 自体が typecheck・単体テスト・データ検証を回しているが、browser・security は走らない。GitHub は `workflow_dispatch` だけは GITHUB_TOKEN からの起動を許しているので、`checks.yml` に `workflow_dispatch:` を足し、publish の最後に `gh workflow run checks.yml --ref automation/official-budget-requests` を呼べば、通常の 3 ジョブが更新ブランチで揃う。別 PR でよい。

### 低 3. 日次継続の cron が毎日 checkout と npm ci を消費

未完了チェックポイントが無い日も、判定（`plan-budget-request-run.ts`）の前に checkout・npm ci・cache 復元（2〜3 分）が走る。順序上やむを得ないので許容。気になるなら日次 cron を外し、週次実行の末尾で未完了時に `gh workflow run` で翌日を予約する形もある。

### 低 4. 警告表示の色が生の Tailwind 色（`app/budget-requests/view.tsx`）

`bg-amber-50 text-amber-900` を 6 か所で直接使っている。デザインシステムの状態トークン（`bg-status-*-bg` / `text-status-*-fg`、`client/components/quality/score-meta.tsx` 参照）に揃える。

### 低 5. `contents: write` の範囲

GITHUB_TOKEN に `contents: write` を与えるため、理屈上は任意ブランチへ push できる。スクリプト側で専用ブランチに限定しているのでコードの問題ではないが、main のブランチ保護（直接 push 禁止・必須チェック）が無人更新の最後の防波堤になる。設定側で確認する。
