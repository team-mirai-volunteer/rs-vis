# PR #25「概算要求の自動取得・原資料検索」レビュー

対象: https://github.com/team-mirai-volunteer/rs-vis/pull/25（`feat/budget-request-acquisition` → `main`、38ファイル・+2,539行、head `2bca121`）。
`git show origin/feat/budget-request-acquisition:<path>` で読み、同梱の `budget-requests-2027.json.gz` の実データと `officialUrl` の実行テストで検証した。CI（validate・security・browser）は成功済み。

## 結論

**このままマージしない。** コードの作りは丁寧で、セキュリティ（政府ドメイン限定・リダイレクト再検証・金額の0円化禁止）と層の分離は守られている。ただし「毎日 main に直接コミットして本番デプロイする」ワークフローの設計に実害のある問題が2つあり、抽出にも金額行を黙って落とすバグがある。高の3件を直してからマージするのが良い。

## 重要度: 高

### 1. 毎日必ずコミット・本番デプロイが走る（`scripts/fetch-budget-requests.ts:102`、`.github/workflows/budget-requests.yml:40`）

`snapshot()` が毎回 `generatedAt` と全取得資料の `retrievedAt`・`lastAttemptAt` を現在時刻で書き換えるため、原資料が1バイトも変わらなくても gz は毎日差分になる。ワークフローの `git diff --cached --quiet` は機能せず、毎日 main へ約1.9MBのコミット（年間約700MB のリポジトリ増加）と Vercel 本番デプロイが無条件に発生する。
対策: レコード内容と原資料ハッシュが不変なら前回の `generatedAt` を維持する。または `generatedAt` を除いた内容ハッシュを比較してからコミットする。

### 2. 科目コードが2 glyph に割れた明細行が金額ごと黙って消える（`scripts/budget-requests-extract.ts:224-235`）

科目コードを1つの text item に限定して正規表現照合するため、PDF.js が「31021-」と「306-22-2500」に分けた行は「未解決の明細行」として除外される。同梱データでは16資料・1,201行がこの理由で落ちており、復興庁の歳出概算要求書だけで362行（例: 復興債償還財源 47,658,341 / 63,923,795 千円）。親の小計不一致27件の一因でもある。資料単位の警告しか残らず、UIでは「その要求が存在しない」ように見える。
対策: `left` の隣接 glyph を結合してからコード照合する。

### 3. 本番への直接 push と運用の脆さ（`.github/workflows/budget-requests.yml:16, 27`）

- `contents: write` で `git push origin HEAD:main`。レビューも validate CI も経由せずに main が動く。ブランチ保護があれば毎日失敗、無ければ毎日デプロイ（1 と合わせて）。
- 初回フル取得（発見1,453件のうち取得済み241件、既定 `--max-files 2000`）は数百MBのPDFを座標抽出するため90分に収まらない可能性がある。CI ではキャッシュ dir が永続化されず `--resume` も使わないため、タイムアウトすると翌日も最初からやり直しで何もコミットされない。
- push が non-fast-forward で拒否された場合の再試行がない。

対策案: (a) データ更新は `data/` 系ブランチに push して PR を自動作成する（既存の dependabot と同じ流れ）、(b) `data/budget-requests/sources` を `actions/cache` に載せて `--resume` を使う、(c) 日次ではなく週次にする。概算要求資料は8月末の提出後ほとんど変わらないので、日次で1,453件を再取得する必要は薄く、政府サイトへの負荷の点でも週次か条件付き取得（If-Modified-Since / ETag）が望ましい。

## 重要度: 中

### 4. `validation` 配列が前回オブジェクトと共有され、注記が毎日増える（`scripts/fetch-budget-requests.ts:88, 139, 154, 169, 174, 196`）

`register()` が `{ ...old }` の浅いコピーのため、取得されなかった資料（上限超過・深度超過・再発見できず）には毎日同じ注記が push される。3回実行すると「再発見できませんでした」が3件並ぶ。
対策: コピー時に `validation: [...old.validation]` とし、当該 run の注記だけ付け直す。

### 5. 列境界を見出しの中点で固定しているため桁数の多い金額が隣列に紛れうる（`scripts/budget-requests-extract.ts:205, 239-240, 253-254`）

右詰め金額が境界を跨ぐと左側の桁が隣列に入り、残りの桁だけが `numeric` として確定する。`validateRequestYearComparison` は比較欄が数値のときだけ検出するので、比較欄が空白・事項要求の行では誤った金額が残り得る。同梱データでは顕在化例0件だが、桁数の大きい特別会計表で起こりうる。
対策: 数字 glyph の連続を列として扱うか、比較欄が非数値の行で列幅超過を検出して `extraction_failed` にする。

### 6. 国会図書館のウェブアーカイブ（`warp.ndl.go.jp`）が政府ドメインとして通る（`scripts/budget-requests-discover.ts:14, 98`）

go.jp ドメインだが任意サイトの過去スナップショットを配信する。同梱データでは2023年のアーカイブが「歳出予算」資料として登録されており、年度ラベルのないリンク先がたどられると2027年度要求として取り込まれうる。
対策: `warp.ndl.go.jp` を除外、または URL 中のタイムスタンプ年を年度判定に使う。

### 7. ナビゲーションの位置（`components/navigation/pages.ts:10`）

「概算要求（試作）」が主ナビの2番目（サンキー図の直後）に置かれている。RS 照合は全件 unmatched、抽出は57資料にとどまる試作なので、他の試作（基金・事業者別・租税特別措置）と同じく後方に置くのが自然。

## 重要度: 低

### 8. 「対前年度増減額」を前年度額と誤判定しうる（`scripts/budget-requests-extract.ts:304-307`）

`fieldForHeader` が `前年.*額` で `previousYear` と判定する。前年度予算額列があれば重複検出で unsupported になるが、CSV に「要求額・対前年度増減額」だけの場合は増減額が前年度額として保存される。

### 9. 同一 run 内で時刻がずれる（`scripts/fetch-budget-requests.ts:94`）

`acquire()` が `options.now` 未指定時に呼び出しごとの `new Date()` を使い、`sourceDocument` の `now` や `generatedAt` とずれる。日付を跨ぐと `--resume` のキャッシュ判定が外れる。

## 正しいと確認した点

- `officialUrl`（discover.ts:11-18）: `evil-go.jp`、`go.jp.evil.com`、`mof.go.jp.evil.com`、userinfo、非既定ポート、`javascript:`、末尾ドット、`go.jp` 単独をすべて拒否。リダイレクトも1回ごとに再検証（fetch.ts:21）。
- `parseRequestAmount`（extract.ts:37-53）: 単位不明・円に割り切れない端数・非 safe integer は `extraction_failed`、空欄は `blank` で0円化しない。△/▲/全角/区切り混在も NFKC 後に処理。同梱21,147行はすべて千円単位・負数772行で整合。
- `app/lib/budget-requests.ts`: status/type/ministry フィルタが documents→records の両方に一貫適用され、ページングに off-by-one なし。`requestSourceUrl` は http(s) のみ許可し、view.tsx は文字列をすべて React のテキストとして描画（XSS なし）。`save()` は tmp→rename で原子的。
- 層の規則: scripts は app を import せず、`app/lib/budget-requests.ts` は型のみ依存で純粋、API は app/lib に委譲。データローダーは .gz フォールバックがあり、prebuild の同期対象にも自動で入る。
- `git diff origin/main` に見える利用規約/プライバシーリンクの削除は merge-base の差（main 側で後から追加）で、このブランチの変更ではない。3-way マージでは保持される。マージ前に main を取り込んでおくのが安全。
