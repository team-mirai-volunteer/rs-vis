### レビューに無かった追加の問題

- **/budget-sankey の歳入列見出し**：`UnifiedSankeyChart.tsx:544` の歳入列見出しが「当初予算・会計間受入含む」で固定されている。既定の決算ベースでも歳入データは決算（収納済歳入額）なので、**見出しのほうが誤り**。`UnifiedViewSelect.tsx:119` の「歳入は当初予算に収録」も同様。レビューの「歳入側は当初予算、支出側は決算」という前提は古いが、画面上はそう読めてしまう
- **自前財源比率**：`generate-mof-budget-overview-data.ts:164` は公債金・借入金・前年度剰余金受入を「自前」に含めている。また、全体集計では除外している「他勘定より受入」を、会計別の比率では除外していない
- **実質支出額と直接支出合計は別の集計**：レビューは「同じなら揃える」としているが、実際は集計方法が違う。実質支出額は5-2 の根ブロックに属する支出先別合計で、5-2 が無い事業は総額にフォールバックする（`score-project-quality.py:233-242`）。直接支出合計はブロックの合計額で、別財源ブロックを除外する（`generate-subcontracts.ts:483-490`）。名前だけ揃えると、かえって誤解を招く
- **「終了・廃止候補」の判定方法**：順位帯（overallPercentile ≤ 5）に、軸ごとのパーセンタイル条件を組み合わせている（`policy-evaluation.ts:231,301-306`）。「縮小」は不用率と1億円以上という絶対額、「収支是正」は budgetConsistency < 60 という絶対閾値で決まる。「母集団内の順位帯で判定」という説明（`QualityHelp.tsx:27`）は、この2つには当てはまらない

## 2. AI評価の位置づけ（優先度：高・方針判断が必要）

- 説明では「材料がどれだけそろっているかの目安」としている（`QualityHelp.tsx:15`、`UnifiedHelp.tsx:63`）
- 一方で、軸の説明と採点プロンプトは中身を判断している。例：「そもそも要るのか」、受益者が国外主体のみなら上限5、受益者負担が相当なら上限6（`score-meta.tsx:54-70`、`scripts/score-project-quality-ai.py:609-613,716-719`）。「終了・廃止候補」の理由文も「廃止した場合に困る主体を特定できず」である
- 指摘は妥当。**記載充実度の評価に寄せるのか、独自基準の政策評価として明示するのか**を決める必要がある。前者ならラベル変更（重点確認候補・金額差の確認）とプロンプトの見直しまで必要になる。後者なら、タイトルと評価主体・基準の明示で足りる

## 4. 年度表記

RS系のページは `app/lib/rs-fiscal-year.ts` で統一されている。それ以外は「年度／年版／シート年度／予算年度／要求」と、暦年「年」と年度「年度」が混在している（税負担は「2025年版」のモデルで「2024年の」データ、財政余力は「2024年度実績」と「2024年実績」など）。表記ルールを決めてから一括で揃えるのがよい。
