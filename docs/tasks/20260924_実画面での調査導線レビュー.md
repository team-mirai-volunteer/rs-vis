# 実画面での調査導線レビュー

実施日: 2026-09-24。対象: ローカル作業ツリー（HEAD e2b6fc6）、Next.js 開発サーバー、実データ。

## 結論

検索から支出先・委託構造・評価詳細へ進む基本動線と、共有URLの復元は動作した。次の優先事項は、ブロック数の集計不一致、年度の意味の説明、スマホ詳細パネル内の移動しやすさ。

今回はレビューのみ。アプリ・データの修正は行っていない。

## 実施範囲

- Chromiumで画面を操作し、DOMの表示内容とスクリーンショットを確認。PCは1440×900、スマホ幅は390×844。共有確認の一部ではタッチ・モバイル設定も有効化。
- GIGAスクール構想（公立、PID 1503）: トップ → 統合ビュー → 「GIGA」検索 → 事業の支出 → 支出先・ブロック → 委託構造。
- 同事業: 評価一覧の事業詳細 → スコア計算根拠 → 詳細URLコピー → 新規ブラウザコンテキストで復元 → 閉じて一覧へ。
- マイナンバー制度の推進（PID 7）: 委託構造一覧 → フロー図 → ブロック図。読売広告社ほか → 博報堂DYメディアパートナーズほか → 白組ほか、の再委託を確認。
- バブルチャート: スマホ幅で絞り込みを開く → 「GIGA」検索 → 表で見る → 私立学校の事業（PID 7614）を選択 → URLを新規PCコンテキストで開き、同じ事業詳細の復元を確認。
- 上記探索はAPIのモックなし。既存E2Eは `public-ux.spec.ts` と `quality-share.spec.ts` の12件を実行し、全件成功（50.9秒）。既存テストにはコメントAPIのモックがある。

## 優先度1: 同じ事業のブロック数が一致しない

再現:

1. `/quality?year=2025&detail=1503` を開く。概要に「ブロック:2件」、計算根拠にも「ブロック数 2」。
2. `/subcontracts/1503?year=2025` を開く。「ブロック 3」。A・B・Cの3ブロックが存在する。

`scripts/score-project-quality.py` は `ps.block_names.add(block_name)` で名前を集合に入れ、その件数を `blockCount` に出力している。実データではAとCが同じ「東京都ほか」、Bが「京都市ほか」のため、3ブロックが2名称に集約される。表示不一致と整合するコード上の原因を確認した。データの再生成による検証は未実施。

提案: ブロック番号で数える。名前の種類数が必要なら別の指標名にする。修正時は同名・別番号の事例を回帰テストにする。現画面ではブロック構造はスコア不算入と説明されており、この件だけで総合点の誤りとは判断しない。

証拠: [評価詳細](../../.tmp/ux-review-20260924/quality-mobile.png)、[委託構造](../../.tmp/ux-review-20260924/subcontracts-desktop.png)。

## 優先度2: 画面を移ると年度の意味が変わる

GIGA事業を統合ビューの2024年度で選び、「フローを見る」から移動すると、委託構造は2025年度になる。評価一覧へのリンクも `year=2025`。

執行年度とレビューシート年度を対応させる動作として理解できるが、画面上部の選択肢はいずれも単に「年度」で、別年度の事業に移ったように見える。金額の相違がある場面では特に混乱しやすい。

提案: 詳細の上部などに「2024年度の支出／2025年度レビューシート」を表示する。年度を機械的に同じ値へ揃える修正は避け、基準の意味を揃えて説明する。

## 優先度3: スマホの詳細パネルで次の操作が見つけにくい

390×844でGIGA事業の支出を選択すると、詳細パネルは約439pxの高さ。タイトル・金額・属性・評価で大半を使い、タブ列が画面下端付近になる。「必要性」は評価の2段目に折り返す。支出先・ブロックのタブは横方向の移動も必要。

操作自体は可能で、支出先・ブロック・委託構造への移動は成功した。ただしPlaywrightによる自動スクロールも含むため、人が直感的に発見できることの証明ではない。図のズーム操作もパネル右下に重なる。

提案: モバイルではパネルを拡大できるようにする、概要を圧縮する、タブを見える位置に固定する、の順で小さく試す。図の操作ボタンと詳細の操作領域を重ねない。

証拠: [選択直後](../../.tmp/ux-review-20260924/giga-mobile.png)、[委託構造](../../.tmp/ux-review-20260924/subcontracts-mobile.png)。

## 優先度4: 初期サンキーの列見出しと操作パネルが重なる

1440×900の統合ビューで表示件数の操作群が2行になり、2行目の「支出先」操作が左側の列見出しに重なる。スマホでは横に広い図の一部を表示する形になり、長い列見出し同士も重なって見える。

提案: 操作群の実際の高さに合わせて図の見出し位置を確保する。全ラベル表示の方針は維持しても、見出しの重なりは独立して解消できる。

証拠: [PC初期表示](../../.tmp/ux-review-20260924/sankey.png)、[スマホ初期表示](../../.tmp/ux-review-20260924/sankey-mobile.png)。初期画像の一部にはポインター位置によるホバー強調を含む。

## 優先度5: 数字の違いの説明へ到達するまでが長い

GIGAの検索結果には当初予算5.08億円と支出2085.45億円が並ぶ。委託構造まで進むと、予算・執行の内訳に前年度繰越1919億円や補正予算が表示され、予算総額2190億円との関係を確認できる。

必要な情報はある。初見では極端な予算超過に見えるため、事業詳細で「当初予算」「繰越・補正を含む予算」「支出」の関係を短く示すと理解しやすい。

評価根拠も確認できたが、事業内容の長文の後に続く。評価理由を知りたい人には、冒頭の要点や該当箇所への移動があると便利。

## 良かった点

- 評価詳細の共有URLは、保存状態のない新規コンテキストでも同じ事業を開いた。スマホでもダイアログは画面幅内に収まる。
- バブルチャートも、検索条件と選択事業を含むURLから別コンテキストで復元できた。
- 再委託は直接支出と別の階層で追え、フロー図とブロック図を切り替えて支出先・役割を確認できる。
- 評価根拠には暫定値・欠測の扱い・重み・不算入項目の説明があり、点数だけで終わらない。

## 限界

本番環境・実機Safari・低速回線・全事業は未検証。外部RSサイトの内容との照合、AI評価の妥当性監査、財政シミュレータのモデル検証は対象外。金額はこの作業ツリーの表示を記録したもので、一次資料との独立照合ではない。

探索中のスクリプトには、件数付きタブ名を完全一致で探したことや、スマホの折り畳み内の検索欄を開く前に入力しようとしたことによる失敗があった。これらは手順を修正して完了しており、アプリの機能不良には数えていない。

このレビューは操作上の問題を見つけるためのもので、初見の人による利用テストの代わりではない。
