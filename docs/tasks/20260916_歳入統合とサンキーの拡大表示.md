# 歳入統合とサンキーの拡大表示

## 歳入 → 会計 → 事業 → 支出先

統合サンキーの当初予算（2023〜2026年度）に歳入列を追加。「統合」「予算書のみ」で初期表示し、RSのみでは表示しない。`cols=rv,ac,...`、表示数 `trv`、表示位置 `orv`、歳入ノードの `sel` を共有URLで保存する。

既存のMOF予算全体ビューでは特別会計の財源が合算されているため、その比率で個別会計へ割り振らず、公式CSVの「特別会計」列から直接接続する。一般会計の租税は目名（所得税、消費税など）、その他は款名で集計する。年金の保険収入に含まれる「一般会計より受入」や、一般会計の諸収入に含まれる特別会計受入金は、行単位で分離して一度だけ数える。

会計・勘定間の受入を灰色で区別する。歳入列の合計は純計の財源ではなく、受入を含む総額。税目から個別事業への充当を確定できるデータではないため、詳細・ツールチップに表示上の按分である旨を示す。歳入列を表示するときは会計列を残し、列の畳み込みによって税目→事業の直接リンクを作らない。

歳入が歳出を超える場合、会計の金額は歳出予算を保持し、図の太さだけ両側の流量を収める。詳細には元の歳入総額を別に表示する。補正・決算には当初の歳入を流用しない。

## 出典・再生成

公式の[令和6年度アーカイブ](https://www.bb.mof.go.jp/archive/reiwa6.html)等に掲載された科目別CSVを使用。各年度の以下のZIPを `data/download/mof_{年度}/` に配置する。

- `https://www.bb.mof.go.jp/server/{年度}/csv/DL{年度}11001.zip`（一般会計）
- `https://www.bb.mof.go.jp/server/{年度}/csv/DL{年度}12001.zip`（特別会計）

`scripts/unified-budget-revenue.ts` がCSVを集計し、URL・ZIPのSHA256・取得日をグラフの `metadata.revenueSources` に記録する。CSVの千円単位を円へ変換する。

`tsx scripts/generate-unified-budget-graph.ts --budget-year {年度} --sheet {RSシート年度} --basis initial` を実行後、生成JSONをgzipにしてGit管理する。RSシート年度は2023年度が2024、2024〜2026年度が2025。

## ズームと文字サイズ

統合サンキーのズームはSVG全体の等方拡大縮小に変更。ホイールはカーソル位置、ボタン・数値指定は画面中央、ピンチは二本指の中点を基準にする。ズームでノード配置や帯の縮尺を再計算しない。ミニマップの表示範囲・移動にも倍率を反映する。

文字サイズは文字・白い縁取り・ラベル間隔・列幅に連動する。帯の縮尺計算用の行間 `scaleNodeSlot` と、表示用の行間 `minNodeSlot` を分離し、文字サイズによって金額を表す太さが変わることを防ぐ。これは統合サンキーに適用し、他ビューの配置計算は従来の既定動作を維持する。

## 検証

- 単体241件成功。税目、千円→円、受入の二重計上、会計と帯の値の分離、文字サイズと帯幅の独立性を検証。
- 4年度の歳入総額・一般会計税目別・特別会計の自前財源が、別パイプラインの既存MOF予算全体集計と完全一致。
- 変更前のGitデータと比較し、4年度の既存歳出ノード・エッジ・総計が全て不変であることを確認。
- 生成物検証は2024〜2026年度の全項目が成功。2023年度は既存の未突合16.62%が閾値3%を超える。歳入追加前後で当該値は不変で、エッジ参照・列順・中間列の収支・会計総額の検査は成功。
- 本番ビルド（型チェックを含む）成功。関連ブラウザ25ケースを確認。歳入の出典・共有URL、基準切替、PCのズーム・ラベル変更、スマホの二本指ピンチ、検索・絞り込み・表示数・ナビ遷移を含む。
