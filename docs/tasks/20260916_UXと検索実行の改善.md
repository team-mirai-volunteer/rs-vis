# 公開画面と検索実行の改善

## 検索の計算量

公開API `/api/mof-hierarchy` の項名・事項名と `/api/mof-sankey` の項名フィルタが、利用者のパターンをJavaScript標準RegExpで実行していた。

照合を共通の `compileSearchPattern` へ集約し、[RE2JS](https://github.com/le0pard/re2js) 2.8.6へ変更。128文字制限、数指定の繰り返し展開上限1,000、キャッシュ最大128件を設けた。先読み・後読み・後方参照など非対応の構文は400を返し、フィルタを無視して全件を返す動作を廃止した。通常の部分一致は維持する。統合ビュー、ローカル用Sankey query、共通文字列フィルタも同じ照合を使う。

長い不一致文字列に対する入れ子の繰り返し、パターン長、繰り返し数、構文、公開APIの応答を回帰検証する。長さ制限だけをReDoS対策とは扱わない。

## focusの共通化

階層・項×RS・統合の3コピーを `sankey-focus.ts` に集約。列順と下流補正対象の違いは各アダプターで指定する。階層・項×RSは集約ノード、統合は全下流ノードを補正する既存仕様を保持。

複数親の按分、共有された下流、関係のない兄弟、未知ID、ゼロ額、通過ノード、元データ非変更を3アダプターそれぞれで検証する。祖先から子孫へ直接流れる辺が選択ノードを迂回する場合、その寄与を混ぜないよう修正した。

## 画面

- サンキー図のh1「国の予算と支出の流れ」は読み上げ用に保持し、図の表示領域を確保するため可視の説明ヘッダーは置かない。初期ラベル密度は全表示、文字サイズは13px。`ld=major` を指定した共有URLは主要ノード表示として復元する。
- モバイルの評価一覧はカードにし、府省庁・PID・事業名・総合点・推奨・予算額・執行額・詳細ボタンを横スクロールなしで表示。検索と並び順も手元に置く。PCの表は維持する。
- ホームとナビ掲載の12ページに固有title・description・canonical・OG・Twitterカードを設定。1200×630 PNGは既存ロゴとコードで描画し、`scripts/generate-social-images.ts` で再生成できる。ページ単位のカードであり、事業ごとの動的画像ではない。

## 検証結果

単体232件、ブラウザ28件、型チェック、本番ビルドが成功。ブラウザ検証には公開APIの応答、JavaScript実行前のtitle・OG・TwitterメタデータとPNG実体、モバイルの評価と詳細導線、サンキー選択・検索・共有URL・表示年度、既存の評価詳細共有を含む。共有画像と390px幅の評価一覧は画像でも確認した。

## 追加の表示調整

- 共通ヘッダーをルートレイアウトで保持。ページの `AppHeader` は配置用の余白とコントロールのポータルを提供し、年度選択などの状態・イベントは各ページが持つ。ビュー切り替え時もロゴ・主要ナビ・ハンバーガーメニューのDOMを作り直さない。
- 委託構造の表見出しは折り返して全文表示。差額の列も「支出額合計 − 直接支出合計」「執行額 − 直接支出合計」と明記する。
- 政策額スライダーはOS既定の軌道色を使わず、既存の薄灰色トークンを適用。つまみとキーボードのフォーカス表示は緑を維持。
- サンキー図は説明帯を削除し、全ラベル表示を既定に戻した。統合・階層・項×RSの既定文字サイズは13px。URLで明示した表示設定は引き続き復元する。

追加変更後は本番ビルド（型チェックを含む）と関連ブラウザ22ケースを確認。PC・モバイルのメニュー遷移、主要ナビ、戻る操作でヘッダーの同一DOMが保たれることと、遷移先の年度選択を検証。スライダーの矢印キー操作、委託構造の23列の見出しに横方向の欠けがないこと、PC・モバイルの表示も確認した。
