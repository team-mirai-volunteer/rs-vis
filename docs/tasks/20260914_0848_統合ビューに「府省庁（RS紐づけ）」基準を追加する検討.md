# 統合ビューに「府省庁（RS紐づけ）」基準を追加する検討

## 提案

予算の基準セレクト（当初予算 / 補正予算 / 決算）に 4 つ目「府省庁」を足し、
旧サンキー図と同じ **RS システムの府省庁 → 事業** の紐づけで見られるようにする。

## 結論

**実装できる。追加のデータ生成は要らない**（クライアント側の変換だけで済む）。工数は半日程度。

理由: 統合グラフの事業ノードは既に `rsMinistry`（RS 側の府省庁名）を持っている（生成時に sankey-svg から引き継いでいる）。
事業(支出) → 支出先のリンクも入っているので、所管〜目の MOF 側を捨てて
`府省庁(RS) → 事業 → 事業(支出) → 支出先` を組み直せば旧サンキー図の流れになる。

## なぜ欲しいか（効果）

| 現状の問題 | 府省庁基準での見え方 |
|---|---|
| RSのみプリセットでも所管は MOF の名前（「内閣府及び厚生労働省」）。RS の「厚生労働省」と一致しない | RS の府省庁名で並ぶ。旧サンキー図と同じ |
| 目 → 事業の突合が不完全な年度（2023 は未突合 17〜20%）では事業の値が「目に対応しない分」経由になる | 突合を使わないので 2023 も RS の値がそのまま出る |
| 事業の値が目からの流入に丸められる（流入 > RS 値のとき） | RS シートの値のまま |
| 旧 URL の `fm=府省庁名` を統合ビューへ写せなかった（体系が違う） | 府省庁基準 + 所管絞り込みに写せる |

## 設計

### データ

- ファイルは既存の `unified-budget-{年度}-initial-graph.json` をそのまま読む（府省庁基準は「当初予算」ファイルの上に載せる）。
- `toViewGraph` の手前に純関数 `toRsMinistryGraph(graph)` を足す（`app/lib/unified-budget/transform.ts`）:
  1. 会計・組織/勘定・項・目・事業区分（非事業支出・未突合・outside）のノードとリンクを捨てる
  2. RS 事業ノードごとに `min-rs-{rsMinistry}` を作り、`府省庁 → 事業` のリンクを事業の値で張る
  3. 事業 → 事業(支出) → 支出先はそのまま
  4. 府省庁ノードの値 = 配下事業の合計
- 事業の値は当初予算ファイルの `value`。ただし生成時に「流入に合わせた」事業（overLinked。2024 で数十件）は RS 値が失われているので、
  生成側で `rsValue`（シートの値そのまま）を事業ノードに 1 フィールド足して再生成するのが正確。
  暫定なら現在の `value` で始めてよい（差は小さい）。

### 基準の型

- `UnifiedBasis` に `'ministry'` を足す（ラベル「府省庁」、MOF 側の指標ラベルは無し、RS 側は「当初予算」）。
- 府省庁基準では使える列が `ministry, program, program-spending, recipient` だけになる。
  `availableColumns` をこの 4 列に絞れば、プリセットは自動的に「RSのみ」相当になり、表示設定の列トグルも他列が消える（既存の 2026 年度と同じ扱い）。
- 列見出しは `所管_2024` ではなく `府省庁_2024`（RS）に変える（`UNIFIED_COLUMN_LABELS` を基準で差し替え）。
- URL は既存の `b=` に `ministry` を足すだけ。年度ごとの `UNIFIED_BASES_BY_YEAR` に全年度で追加（2026 要求ベースも RS しか無いので自然に対応）。

### 絞り込み・選択

- 所管絞り込み（`fmi`）はノード名一致なので RS 名で動く。ノード ID は `min-rs-…` にして MOF の `min-…` と衝突させない。
- `sel=project-budget-{pid}` は事業 ID が共通なので基準を切り替えても選択が残る。
- `/sankey-svg` リダイレクトの `fm=` を `b=ministry&fmi=…` に写せるようになる（`links.ts` と e2e の期待値を更新）。

### 決めること

1. **府省庁基準の事業の値**: 当初予算（提案）か、旧サンキー図の歳出予算現額か。歳出予算現額を出すなら `rsValue` を生成側で足す必要がある。
2. **セレクトの並び**: 当初予算 / 補正予算 / 決算 / 府省庁。府省庁は「予算の基準」ではなく「紐づけの基準」なので、
   セレクト内で区切り線（`optgroup`）を入れて分ける程度に留める（別セレクトにはしない。ヘッダーがもう混む）。

## 手順

1. `transform.ts` に `toRsMinistryGraph` と単体テスト（府省庁の合計 = 事業合計、MOF 列が消える、支出先が残る）
2. `types/unified-budget.ts` に基準 `ministry` を追加、ページで基準に応じて `availableColumns` と列ラベルを差し替え
3. `UnifiedBasisSelect` に選択肢を追加、ツールチップの文言更新
4. `links.ts` の `fm` 写像を復活、e2e（`sankey-svg-redirect.spec.ts`）を更新
5. （任意）生成器に `rsValue` を追加して 4 年度 × 3 基準を再生成

## 実施結果（2026-09-14）

- 事業の値は **当初予算**（ユーザー決定）。当初予算ファイルをクライアント側で組み替える `toRsMinistryGraph`（`app/lib/unified-budget/transform.ts`）を追加。別ファイルの生成はしていない
- 基準 `ministry`（URL `b=ministry`）を全年度で有効化。セレクトは `optgroup` で「予算書の基準 / 紐づけの基準」に分けた
- 使える列は表示グラフに存在する列から求めるようにした（府省庁基準では 所管・事業・事業(支出)・支出先 の 4 列）。所管列の見出しは「府省庁_年度 RS当初予算」
- プリセットの逆引きは列をそのまま比べる判定を先に行い、府省庁基準で「RSのみ」と出るようにした
- **旧 `/sankey-svg` のリダイレクトは府省庁基準で開く**（旧サンキー図は RS 府省庁で紐づけていたため）。`fm=` は `fmi=` へ、`ministry-X` / `pm=X` は `min-rs-X` へ写す
- 単体テスト `tests/unified-budget-ministry.test.ts`、`unified-budget-links.test.ts` と e2e `sankey-svg-redirect.spec.ts` の期待値を更新
- 未対応: 生成時に流入へ丸められた事業（overLinked）の RS 値復元（`rsValue`）。差は小さいので当初予算ファイルの値のまま
