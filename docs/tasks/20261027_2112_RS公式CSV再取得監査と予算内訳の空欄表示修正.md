# RS公式CSV再取得監査と予算内訳の空欄表示修正

## 結論

2件の問題は分けて扱う。

1. **PID 20464の246.4億円は、現在配布中のCSVと現在のRS APIの不整合。** 再取得してもCSVに残っていた。2025年版CSVの契約概要は令和7年度だが、2025年版APIに支出明細はなく、2026年版APIに令和7年度契約2,464万円がある。CSVを単に1,000で割って別年度に残す修正はしない。
2. **文化振興費／諸謝金の0円は、年度の違いとサイトの空欄処理。** RSの2025年版「予算・執行」タブは2025年度予算507千円（50.7万円）を表示し、CSVの2025年度行も507,000円で一致する。一方、当サイトの「2024年度実績」は2024年度行を読む。その予算額は空欄で、サイトが0円に変換していた。

## 再取得の範囲・証拠

- 取得日：2026-10-27
- 取得元：https://rssystem.go.jp/download-csv/2025
- 対象：1-1、1-2、2-1、2-2、5-1、5-2、5-3の主要7本。
- `node scripts/download-rs-csv.mjs 2025` で公式画面のZIPをダウンロードし、`python scripts/extract-rs-csv.py 2025` でUTF-8へ展開。

- **7本とも展開後のSHA-256が再取得前と完全一致。変更事業IDは0件。** ローカルの変換処理が今回の246.4億円を作ったわけではない。
- ハッシュ、件数、API照合結果：[監査マニフェスト](../audits/20261027-rs-csv.json)。原CSV・全APIレスポンス・画面スクリーンショットは `data/audit/20261027-rs-refresh/` に保存（Git管理外）。

## 全CSVの機械監査とAPI照合

CSVの列数を検証し、予算・執行とも0なのに支出明細がある事業、および明細合計が予算の10倍を超える事業を抽出した。

| チェック | 件数 |
|---|---:|
| 2024年度の予算内訳で予算額が空欄 | 1,017行／748事業 |
| 上記のうち翌年度要求額が正の値 | 611行 |
| 予算・執行とも0で支出明細がある | 79事業 |
| 支出明細合計が予算の10倍超 | 5事業 |
| 上記84事業を現在の公式APIで照合 | 84成功／取得失敗0 |
| 支出明細金額合計が一致 | 82事業 |
| 支出明細金額合計が不一致 | 2事業 |

この抽出は検査対象候補であり、不正・誤記の判定ではない。支出明細合計には再委託・複数年度契約・補助金等が含まれ得る。APIとの合計一致は、年度帰属や明細の正しさまで保証しない。全事業の全契約の正誤を検証した監査ではない。

## 諸謝金：同じ年度・列の比較

RS画面をブラウザで開いて「予算・執行」タブを実際に確認した。

確認URL：https://rssystem.go.jp/project/a3703d53-9368-4916-8e88-37eb770288de?activeKey=detailed-breakdown

| 2025年版CSVの予算年度 | 予算額 | 翌年度要求額 |
|---|---:|---:|
| 2024年度 | 空欄 | 2025年度要求：1,053,000円 |
| 2025年度 | 507,000円 | 2026年度要求：512,000円 |

RS画面の明細は「507」「512」を千円単位で表示し、2025年度のCSV行と一致した。上部の年度推移表は `consecutive/budgets/` 等を使い、選択した作成年より後の更新値も表示するため、作成年だけで比較対象を判断しない。

したがって、この予算内訳は「RSに数字があるのにCSVが落としている」とは確認されなかった。2024年度の空欄を2025年度の50.7万円で埋めると、年度の取り違えになる。

## 実装した修正

- 予算内訳の空欄・ダッシュを `null` として保持し、明示された0円と区別。
- 共有の予算内訳カードに「2024年度予算：記載なし」「2025年度要求：105.3万円」のように年度・種別を表示。
- 要求額を予算額へ足さない。内訳が欠ける場合、完全な合計があるかのような差額比較を表示しない。
- サンキー・統合グラフ8ファイルの予算内訳を更新。既存の各事業の予算・要求額合計が変わらないことを確認し、予算内訳以外のノード・エッジ・メタデータは変更していない。
- 2024年版の予算内訳も同じ欠損表現へ更新したが、今回公式から再取得して比較したCSVは2025年版の7本のみ。
- 生成元を修正したため、次回の通常生成でも空欄を0に戻さない。

## 支出CSVの不整合について残る対応

- 公式配布CSVと現在APIのどちらを、どの時点・年版の正として採用するかを明示したうえで、支出データ全系統を一貫して再生成する必要がある。
- 今回の監査では原CSV・支出金額を自動補正していない。246.4億円は既存の支出データに残っているため、確定値として照会・主張に使わない。
- APIの空欄を0円とみなした置換や、金額だけを1,000で割る置換はしない。
- 省庁への送信・サイトへのデプロイは未実施。
