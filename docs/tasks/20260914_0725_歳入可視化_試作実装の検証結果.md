## 2. 修正が必要な点

### 2.1 [P1] 住民税の調整控除が「人的控除差」を過大にとっている

- 場所: `app/lib/tax-burden/simulate.ts` 70〜72行。`deductionDifference = basic − localBasicAllowance …` で、所得税の基礎控除（2025年は所得132万円以下 95万円、336万円以下 88万円…）と住民税基礎控除 43万円の差（52万円・45万円…）をそのまま調整控除の人的控除差に使っている。
- 原制度: 調整控除における基礎控除の人的控除差は **5万円** の定額（地方税法附則。2025年改正の基礎控除上乗せは調整控除の計算に含めない）。配偶者控除 5万円・配偶者特別控除の差額表・ひとり親控除 5万円の扱いは正しい。
- 影響: 課税所得200万円以下（単身なら年収おおむね450万円以下）で住民税を最大 **2万〜2.35万円程度過小** に計算する。
  - 手計算例: 単身・年収300万円。給与所得202万円、社会保険料484,440円、住民税課税所得1,105,000円 → 所得割 110,500円。調整控除は 5%×5万円＝2,500円が正しく、所得割 108,000円＋均等割 4,000円＝**112,000円**。実装は調整控除 22,500円で **92,000円**（差 20,000円）。
- 翁カーブの読みへの影響: 低中所得帯の純負担率を 0.5〜0.8ポイント低く描く。「住民税非課税の外れ」以降の立ち上がりが実際より緩く見える。

### 2.2 [P1] 児童扶養手当の所得判定で社会保険料を二重に控除している

- 場所: `simulate.ts` 76行 `assessed = reference − 80000 − social`。
- 原制度: 児童扶養手当の所得 ＝ 所得額 − **8万円（社会保険料相当額の一律控除）** − 諸控除（障害者・寡婦・医療費・雑損・小規模企業共済等）。実際の社会保険料控除は諸控除に含まれず、8万円がその代替。したがって `− social` は不要。
- 影響: 判定所得を実際の社会保険料額（年収250万円で約37万円、300万円で約48万円）だけ低く見るため、全部支給の範囲が広がり一部支給額も過大になる。
  - 手計算例: ひとり親・子2人・年収250万円。給与所得167万円 − 8万円 ＝ 159万円は全部支給限度（69万＋38万×2＝145万円）を超え **一部支給** が正しいが、実装は 121.6万円と判定し **全部支給 675,000円/年** を返す。一部支給の逓減係数（2.3参照）次第で年 4〜5万円程度の過大。全部支給→一部支給の段差位置も年収で約40万円ずれる。
- 2.1 と逆方向に効くため、ひとり親カーブでは誤差が相殺して見えることがある。両方とも修正すること。

### 2.3 [P2] 児童扶養手当の一部支給の逓減係数が未照合

- `singleParentFullMonthly 45,500`・`ExtraMonthly 10,750`・所得制限 69万／208万＋38万×人数 は2024年11月改正の値と一致。一方、`0.025`・`0.0038561` の係数は年度ごとに告示で改定される値で、パラメータの注記でも「原制度との照合は未完了」。2025年1月1日時点の告示値に置き換えるか、注記に「係数は概算」と明記して画面の計算条件にも出すこと。

### 2.4 [P2] 森林環境税（均等割に年1,000円）が未収録

- `localPerCapita 4,000` は都民税1,000円＋特別区民税3,000円で、2024年度から全員に課される森林環境税1,000円を含まない。注記には「未収録」と書かれているが、定額1,000円を足すだけで解消するので入れるべき。非課税判定（均等割非課税なら森林環境税も非課税）は既存の分岐と同じでよい。

### 2.5 [P2] `URLSearchParams.size` に依存しており、古いブラウザで共有URLが無視される

- `app/lib/tax-burden/reform-url.ts` 13行 `if (!q.size) return …`。`size` は Chrome 113／Safari 17／Firefox 112 以降（2023年）のプロパティで、未対応環境では `undefined` → 常に真となり **クエリがあっても既定状態を返し、警告も出ない**。`q.toString() === ''` などに置き換えること。

### 2.6 [P3] 気づいた小さな点

- ブラウザスモークテストは `public/data/*.json`（生ファイル）を読むため、`generate-tax-burden-data` 未実行の環境（クリーンな CI）では失敗する。テスト前に生成するか `.gz` を読むようにする。
- 歳入ビューは UI が2025年度固定（API は2017〜2026対応）。試作としては問題ないが、内訳表の見出し「予算額」の隣に年度セレクタが無いことは実装記録どおり後続扱い。
- 6類型の1つを「単身・子2人（ひとり親）」にしている。設計書の6類型（単身／片働き／共働き × 子なし／子2）とは異なるが、OECD TaxBEN の標準6類型と同じ構成であり妥当。設計書側の記述を合わせてよい。
