# 事業コメント機能（みらい議会ライク）設計

日付: 2026-08-28
ステータス: 設計（実装は Supabase 接続後）

## 要件（ユーザー決定事項）

- 対象者: **サイト訪問者（一般公開）**
- 投稿フロー: **みらい議会ライク**
- 表示場所: 4面すべて（サンキーのサイドパネル / 評価の詳細ダイアログ / バブルの選択パネル / 委託構造の事業詳細）

## 「みらい議会ライク」の意味（調査結果）

チームみらいの「みらい議会」の意見投稿は、コメント欄への自由記入ではなく:

1. **AIインタビュー形式** — AIが対話で意見を聞き、深掘りの質問を重ねて論点を引き出す
2. **匿名** — 投稿者情報は公開しない
3. **本人の同意ステップ** — 「この内容で公開してよいか」を確認し、許可した意見だけを掲載
4. **集約・活用** — 集まった意見は論点発見に使う

出典: [みらい議会公開ノート](https://note.com/team_mirai_jp/n/nd1656aa5f86d)、[AIインタビュー機能リリースノート](https://note.com/team_mirai_jp/n/n11ae2a019cc6)

## アーキテクチャ

```
[事業詳細UI(4面)] ── ProjectComments 共通コンポーネント
      │  意見一覧(GET)             │ 「意見を伝える」→ AIインタビューモーダル
      ▼                            ▼
GET /api/projects/[pid]/comments   POST /api/projects/[pid]/interview  ← LLM(OpenRouter/既存SANKEY_AI_CHAT基盤を流用)
      │                            POST /api/projects/[pid]/comments   ← 同意確定時のみ保存
      ▼                            ▼
   Supabase Postgres（service role 経由のみ書き込み。クライアント直書きはしない）
```

### DB（Supabase）

```sql
create table project_comments (
  id           uuid primary key default gen_random_uuid(),
  pid          text not null,
  year         int  not null,
  body         text not null,          -- 公開する意見（インタビューから整形した本文）
  transcript   jsonb,                  -- インタビュー全文（非公開・運用参照用）
  status       text not null default 'published',  -- published / hidden
  ip_hash      text,                   -- レート制限・荒らし対応用（ソルト付きハッシュ）
  created_at   timestamptz not null default now()
);
create index on project_comments (pid, year, status, created_at desc);

create table rate_limits (              -- サーバレスでも効くDBベースの簡易レート制限
  ip_hash text, window_start timestamptz, count int,
  primary key (ip_hash, window_start)
);
```

RLS: `project_comments` は anon キーで `status='published'` の SELECT のみ許可。INSERT/UPDATE は
service role（Next.js API Route からのみ）に限定。**anon キーでの書き込みは開けない**。

### API（app/api/ — ロジックは app/lib/ に委譲、レイヤー規約どおり）

| Route | 役割 |
|---|---|
| `GET /api/projects/[pid]/comments?year=` | 公開済み意見の一覧（新しい順、ページング） |
| `POST /api/projects/[pid]/interview` | インタビュー1ターン。既存 `app/api/ai/sankey-chat` と同じ OpenROUTER/env 基盤を流用。システムプロンプトに事業の実データ（名称・予算・執行・評価スコア・支出先上位）を注入し「この事業について意見を聞き、2〜3回深掘りする」役を与える |
| `POST /api/projects/[pid]/comments` | 同意確定。インタビュー内容から整形した意見本文＋transcriptを保存 |

投稿時ガード:
- レート制限: ip_hash あたり 5件/時（rate_limits テーブルで判定）
- 公開前スクリーニング: 確定時に LLM で不適切判定（誹謗中傷・個人情報・無関係）→ NG は `hidden` で保存し公開しない
- 本文上限 1,000 字、インタビューは最大 8 ターン・入力 500 字/ターン

モデレーション運用: 既定は「スクリーニング通過で即時公開」。問題投稿は Supabase ダッシュボードで
`status='hidden'` に落とす（管理UIは作らない。必要になったら追加）。

### UI

- `client/components/comments/ProjectComments.tsx`（一覧＋件数バッジ＋「意見を伝える」）
- `client/components/comments/InterviewDialog.tsx`（チャットUI。既存 ChatMarkdown を流用。
  最後に「この内容で匿名公開する」確認 → 整形プレビュー → 確定）
- 4面に `<ProjectComments pid={} year={} />` を差し込む。表示はコメント数と直近数件＋もっと見る

**主導線: サンキーのAIチャット統合（ユーザー決定 2026-08-29）**
/sankey-svg では、事業を選択（ポイント）した状態で AiChatPanel に意見めいた発言をすると
AIがインタビューモードへ遷移する。留意点:
- モードの明示: インタビュー開始でパネルのヘッダー/配色を切り替え、「意見インタビュー中・
  公開は最後に確認します」を常時表示。解説チャットと混同させない
- 同意ステップは従来どおり必須（整形プレビュー→「匿名で公開する」確定）
- チャットパネルの無い他3面は「意見を伝える」ボタン → InterviewDialog で同じ API に合流

### 環境変数（Terraform の app_env_* で配布）

- `NEXT_PUBLIC_SUPABASE_URL` / `SUPABASE_SERVICE_ROLE_KEY`（server専用）/ `NEXT_PUBLIC_SUPABASE_ANON_KEY`
- 専用フラグは置かない。**必要な env（SUPABASE_URL / SERVICE_ROLE_KEY / LLMキー）が揃っているときだけ有効**
  （既存 SANKEY_AI_CHAT と同じ「キーが無ければ機能オフ」規約。ユーザー決定 2026-08-29）。
  実装を先行しても env 未配布の間は UI ごと非表示 = dark ship になる。緊急停止は env を1つ消す
- LLM は既存 `SANKEY_AI_CHAT_*` / `OPENROUTER_API_KEY` を流用

## 実装フェーズ

1. **Phase 1（コードは今から書ける・flagでdark ship）**: DBスキーマSQL、API 3本、共通UI、4面への組み込み
2. **Phase 2（デスクトップ作業後）**: `terraform apply -var supabase_enabled=true` → スキーマ適用（`supabase db push` かSQLエディタ）→ env 配布 → `COMMENTS_ENABLED=true`
3. **Phase 3（様子見後）**: 意見の集約表示（事業ごとのAI要約）、通報ボタン

## リスクと判断

- **荒らし/スパム**: 匿名・即時公開のため残存リスクあり。インタビュー形式は自由記入欄より投稿コストが高く
  抑止になる＋LLMスクリーニング＋レート制限の三段。政治的にセンシティブなら「承認後公開」への切替は
  status の既定値を 'pending' にするだけで可能な設計にしておく
- **LLMコスト**: 1投稿 ≒ 最大9 LLM呼び出し（8ターン+スクリーニング）。レート制限がコスト上限を兼ねる
- **year の扱い**: コメントは pid+year に紐付け（年度でデータが別物のため）。UI では当該年度のものを表示
