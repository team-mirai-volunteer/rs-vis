# AI ナビの補助ビュー対応（概算要求・租税特別措置・国民負担・財政余力）

2026-10-19。AI ナビ（ヘッダーの「AI」）は主なビューの絞り込みと RS データの問い合わせには答えられたが、
補助ビュー 4 つは「ページに移動する」ことしかできなかった。会話で値を答え、条件付きでページを開けるようにした。

## できるようになったこと

| ページ | 会話で答える（データツール） | 条件付きで開く（navigate_page の params） |
|---|---|---|
| 概算要求 | `search_budget_requests`（q・ministry。要求額の大きい順に 10 件） | `q`・`ministry` → `/budget-requests?q=&ministry=` |
| 租税特別措置 | `search_tax_expenditures`（q・year。適用件数・適用額・AI 評価・関連 RS 事業） | `q`・`year`・`linkedOnly`・`view` → `/tax-expenditures?q=&year=&linked=1&view=` |
| 国民負担 | `estimate_tax_burden`（income・household・age・share・includeConsumption。2025 年度制度のモデル計算） | `income`・`household`・`age`・`view`・`includeConsumption` → `/tax-burden?…`（ページと同じ `encodeTaxState`） |
| 財政余力 | なし（計算はブラウザの Worker。会話では答えず、ページへ案内する） | `policies: [{ id, amountYen }]` → `/fiscal-space#scenario=…`（既定の条件に年額を重ねて、ページと同じ符号化） |

- 3 つのデータツールは MCP（`/api/mcp`）にもそのまま載る（`year` は無関係だが他ツールと同じ形で付く）。
- 「いくら？」は移動せずツールで答え、「見せて」「開いて」のときだけ移動する、という使い分けをプロンプトに書いた。

## 実装の要点

- `app/lib/ai/nav-targets.ts`: `navTargetHref(target, params)` がページ固有の条件を URL に写す（Pure）。財政余力は `scenario.amounts` をクライアントに返し、`client/lib/ai/nav-href.ts` が `defaults()` に重ねて `encodeScenario` でハッシュにする（フォームの `amounts` は兆円単位なので円から換算）。
- `app/lib/ai/tool-shaping-secondary.ts`: 3 ツールの整形（サーバ・BYOK クライアント共通）。
- 補助ビューに `query`（サンキー条件）が付いてきても無視する（`QUERY_NAV_TARGETS`）。
- 同じページ内で条件だけ変えるとき（例: 国民負担で「年収を 800 万円に変えて」）は `router.push` ではなく `history.pushState` + `popstate` で知らせ、ページを作り直さない。
- 租税特別措置ページは URL（`q`・`year`・`linked`・`view`）を読み書きするようにした（共有リンクにもなる）。
- `PROMPT_VERSION` を 3 に上げ、応答キャッシュを無効化。

## 残り

- 財政余力の計算結果を会話で答える（エンジンをサーバーでも動かす）は未対応。Node で `createFiscalEngine` を読み込む試行が 3 分で終わらず、まず移動だけにした。
- 概算要求の「府省名」は完全一致。表記ゆれ（「国交省」）はプロンプト頼み。
