# LPの集計条件と説明の修正

## 範囲

`/lp` の数字・AI評価の説明・検索導線を修正する。タイトル、基本レイアウト、議員向けの説明、国会質問14本（うち台本11本）は維持する。本番公開条件は変えない。

作業開始時の `main` は `fbc14c2`。`dev`（`9ae18de`）はPR #20で取り込み済みで、LPは同じ内容。修正は `main` をベースにする。

## 確認した集計条件

- 検査結果の対応事業：`scripts/data/audit-report-matches.json` と `budget-execution-audit-matches.json` の `cases[].pids` はそれぞれ41・60事業。共通10事業、和集合91事業。生成済みデータの `byPid` と一致。指摘278件・調査92件のすべてに事業IDがあるわけではない。LPでは対応表から件数を算出する。
- 対応づけの来歴：両対応表の `reviewedBy` はClaude（AI）による作成、人の確認は未実施。注記はこの値を直接使い、「人手確認を加えた」という誤記を解消する。
- 支出先：`project-quality-scores-2025.json(.gz)` の `recipientCount` 合計は99,292。支出先詳細の行数と一致し、直接支出53,512行・それ以降45,780行。同一法人等を名寄せした数ではないため「延べ支出先記載」とする。
- 1者応札：`contract-methods-2025.json(.gz)` の一般競争・指名競争17,148行のうち、応札者数 `ap` の記載がある16,948行を母数とする。`ap === 1` は8,134行、48.0%。母数には明記された `ap === 0` の96行を含み、未記載200行を除く。政府の全契約に対する割合とは書かない。
- 複数年度の1者応札：事業者別一覧の `repeatSingleCount` は2つ以上の年度に記録がある事業数であり、3年連続を示さない。富士通34事業・NEC38事業の説明を修正。政府に3年以上の契約を調べるよう求める質問案は残す。

## 事務局の金額を置き換えた理由

民間事務局全体の「約4,000億円」は以前の調査記録にあるが、公的主体の具体的な除外条件が保存されておらず、今回の再集計では同じ母数を再現できない。そのため、LPで強調する数字と質問の根拠を、条件を再現できる**株式会社博報堂の事務局関連の直接支出3,027億円**に変更した。民間全体の再推計ではなく、対象を明示した別の集計である。

`project-quality-recipients-2025.json(.gz)` の条件：

- `r === true`、`d === 0`、`a2 > 0`
- `n === '株式会社博報堂'`（すべて法人番号 `8010401024011`）
- `cc`（契約概要）または `role`（役割）が `/事務局|補助事業に関する事務|執行事務|事務費/` に一致

14行・9事業、302,685,876,076円。事業IDは4240、4627、4638、6161、7118、7135、7153、7763、7767。補助金本体を含み、手数料や管理費だけの額ではない。直接支出の判定もレビューシート由来であり、資金の最終到達額を示すものではない。例示は集計内の子育てエコホーム支援事業（209,509,968,380円）に絞った。

別に記載する「46事業・3,634億円」は、支出先名に「博報堂」を含む正の直接支出60行・363,433,549,626円。関連会社・共同事業体を含む名称一致の集計であり、株式会社博報堂だけの数ではない。事業者別一覧は契約方式データを使う別の集計なので、同じ数字を再現できるとは案内しない。

## 説明と導線

- AI評価の説明をサーバー・クライアント共通の定義へ移し、記載内容だけでなく政策上の判断を含むこと、人のレビュー未実施をLPでも明示。
- 一般会計と特別会計の単純合計には重複があるため「国の予算の約27%」を網羅率として使わない。対象範囲の説明に置き換える。
- 年金給付の一律除外を削除。厚生労働省の[令和7年度事前分析表（施策目標Ⅸ-1-1）](https://www.mhlw.go.jp/wp/seisaku/hyouka/dl/r07_jizenbunseki/59_IX-1-1.pdf)は行政事業レビュー番号002826・002827・002828と年金給付に係る事業を掲載している。
- 不用額だけで予算過大とは断定しない。出生行動の変化だけで児童手当拡充の因果効果を特定できるとは書かず、比較対象・他の要因・観測期間を含む調査設計を問う。
- 主導線のサンキー図を維持し、事業検索は `/quality`、企業・事業者検索は `/vendors` に分ける。

## 回帰テスト

`tests/lp-content.test.ts` でデータからの再集計、共有注記、質問14本・台本11本の保持を検証。`tests/e2e/lp.spec.ts` で1440px・390pxの検索導線、企業名検索、戻る操作、質問の開閉、目立つ数値と注意書きの表示を確認する。
