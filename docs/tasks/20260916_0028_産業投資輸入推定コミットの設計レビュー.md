- **レイヤー設計を遵守**。産業連関表の係数取得は `scripts/` の Python、係数の適用と分解は `app/lib/fiscal-space/`、表示は `client/components/fiscal-space/` に分離。`app/lib` に HTTP・React は無い。
- **出典の再現性**。JSON に原数値・SHA256・算式説明を保存し、スクリプトで再生成できる。UI・出典表（`policyTradeRecords`）・docs の3か所で「因果推計ではない」旨を一貫して明示。
- **分解の整合性が検証されている**。`imports = operating − substitution + other` の恒等式と、置換0%/100%を本体再計算した結果の一致をテストで固定。価格時点も基準経路の前年デフレータで統一。
- **旧共有URLの互換性**。モデル版を上げつつ '2026-09-16.2' を受理し、利用者の旧仮定を新係数で上書きしないことをテストで保証。

### ⚠️ 改善提案
- **[app/lib/fiscal-space/policy-trade.ts:155], [client/components/fiscal-space/PolicyTrade.tsx:186], [docs/fiscal-space-long-run-supply.md:16]** 「69.2%・59.7%・19.3%」がリテラルで3か所に重複。スクリプトを再実行して JSON が更新されると文言だけ古い値が残る。
  - 提案: `INDUSTRY_TRADE_REFERENCE` から `(v*100).toFixed(1)` で整形して埋め込む。docs は「JSON を参照」とし数値を持たない。
- **[app/lib/fiscal-space/compare.ts:18]** 置換シナリオ再計算の条件が `incremental.id === 'semiconductors'` にハードコード。直前で `industryConditions`（`trade.kind === 'industry'`）を判定しているので二重条件になっている。
  - 提案: id 判定を外し `industryConditions && annualSalesPerInvestment !== null` のみにする。研究開発など他の産業投資が売上を設定した場合にも同じ内訳が出る。id を残すなら理由をコメントで明記。
- **[app/lib/fiscal-space/compare.ts:35]** `price`/`basePrice` を導入したのに、直下の `energyOperatingTradeEffect` は従来どおり `nominalGdp / realGdp` を再計算している。
  - 提案: 新変数を使って `-(step.demand.projectEnergyNetImports * price - base.demand.projectEnergyNetImports * basePrice) * (1 + shock.energyPriceChange)` に統一。
- **[client/components/fiscal-space/Comparison.tsx:44]** `.map` 内で固定 `id="industry-import-heading"` を出力。現状は半導体のみだが、対象が複数になると id が重複しアクセシビリティ属性が壊れる（発電の既存セクションも同じ書き方）。
  - 提案: `id={\`industry-import-heading-${row.policy.id}\`}` とする。
- **[client/components/fiscal-space/PolicyTrade.tsx:187]** `industryImportBreakEven(industry)` を同じ JSX 内で3回呼び、非 null アサーション `!` を2回使用。
  - 提案: 直前で `const breakEven = industryImportBreakEven(industry);` と一度計算し、`breakEven === null || breakEven > 1` で分岐。
- **[scripts/generate-industry-trade-reference.py:22-30]** 列インデックス 119・121・124・127・129 のうち header を assert しているのは 124 と 129 のみ。e-Stat の表レイアウトが変わると無言で別列を読む。
  - 提案: 119（国内需要合計）・121（輸出）・127（輸入計）の部門コードも `assert sheet[1][...] == '...'` で固定。`r[124]`・`r[127]` が `None` の場合 `-None` で落ちるので `or 0` を揃える。
- **[client/components/fiscal-space/Comparison.tsx:46]** 1行の JSX に table 全体を詰め込んでおり可読性が低い（既存の発電セクションも同様）。
  - 提案: 行の描画を `IndustryImportRow` 等の小コンポーネントへ分ける。
