## 0. 結論（先に要点）

- 新ページ **`/tax-burden`（歳入・国民負担）** を追加し、既存の「歳出（151兆円がどこへ行くか）」に対して「歳入（誰がどれだけ負担しているか）」の視点を補完する。
- データは **2系統** に分ける。
  - **A. 制度シミュレーション系（翁カーブ）**: 税・社会保険料の制度ルールをそのまま計算する決定論的モデル。**条件を固定した定型世帯**（§3.3）について「所得税＋住民税＋社会保険料本人負担 − 現金給付」の **純負担率カーブ** を描く。翁百合氏（日本総研）が国民会議で示した「翁カーブ」（OECD TaxBEN ベース）を、OECD 公開の日本制度説明書に基づいて再現し、消費税・年齢別の日本版拡張を加える。
  - **B. 統計集計系（実態）**: 公的統計の公開集計表を、**その表が持つ軸のまま**（年収階級／世帯主年齢／世帯類型のうち表に存在する組合せのみ）表示する実測の負担率。消費税の逆進性、「1億円の壁」はこちらで示す。
- 両系統を **国の予算上の税・保険料収入**（財務省予算書、既存 `mof-budget-overview` の拡張）に接続し、「どの税が何兆円で、その税は誰に重いか」を往復できるようにする。ただし予算書は **地方税・市町村国保・後期高齢者医療・介護保険料を含まない** ため、「国民負担の全体像」とは呼ばず、指標名と範囲を画面上で明示する（§3.1）。
- 「あるべき税」の検討のため、A系統に **制度パラメータのつまみ** を持たせ、改革案カーブを重ねる。財政影響は **国税収入差・地方税収入差・保険料収入差・給付支出差** に分解して表示し、合算値は「定義した範囲での財政収支への影響」として扱う。全国推計の重み（復元世帯数）が確保できるまで総額表示は出さない（§3.4）。
- 実装はこのリポジトリの定石レールに乗せる: `scripts/generate-tax-burden-*.ts` → `public/data/tax-burden-*.json(.gz)` → `app/lib/tax-burden/*`（純粋ロジック）→ `app/api/tax-burden/*` → `app/tax-burden/page.tsx`。制度ルール計算は `app/lib/` に置き、ブラウザ側でも同じ関数を動かす。

## 1. 目的

- **チームみらいの政策担当者・一般の有権者が**、「税負担が誰に重いのか」を歳出可視化と同じ粒度・同じ場所で見られず、給付付き税額控除や社会保険料改革の議論を **感覚や単発の資料画像に頼っている状態** を解消するため。
- 具体的には次の問いに、数字と図で答えられる状態にする。
  1. 各税（所得税・住民税・消費税・社会保険料…）は、**どの所得階層** に重いか（累進／比例／逆進）。
  2. **どの年齢層**・**どの家族構成**（単身・共働き・片働き・子あり・ひとり親・高齢夫婦）に重いか。
  3. 全部を足し合わせた **純負担率（税＋保険料 − 給付）** は年収に対してどんな形か（＝翁カーブ）。日本の段差はどこで生じ、OECD主要国となぜ違うのか。
  4. 制度を変えると、その形と **国・地方・保険の収支** はどう変わるか。

### 2.3 翁カーブの定義（外部調査結果）

- 提示者: 翁百合氏（日本総合研究所シニアフェロー／NIRA理事）。NIRAオピニオンペーパー No.65（2023）→ No.89（2026）で更新、**社会保障国民会議 2026-03-24 資料11** で「低所得の勤労層への支援の検討―負担率の日・OECD比較」として提示され、給付付き税額控除議論の土台になった。**資料11本体はPDFの本文抽出ができておらず、再現条件の照合は未完了**（Phase 0 で目視確認する）。
- モデル: **OECD tax-benefit model（TaxBEN）**。人口分布は持たず、**定型世帯**（単身／片働き夫婦／共働き夫婦 × 子あり・なし ＝ 6類型）の **平均賃金比 50〜200%** の各点で制度ルールから負担と給付を計算する。日本の制度ルールは OECD が「Tax and benefit policy descriptions for Japan」としてモデル年ごとに公開しており、**2025年版の制度基準日は 2025年1月1日**（原本4ページ「Reference date for the policy rules described in this report: January 1, 2025」で確認済）。**2024年版の基準日は原本未確認**（Phase 0 で確認する。検索結果の要約に依拠しない）。
- **制度年の管理**: R7（自作パラメータ）と R8（OECD 参照値）が別時点の制度を比較しないよう、両方に **モデル年・制度基準日・資料改訂日（PDF の更新日）・取得日・取得元URL・ファイルのSHA-256** を別項目で保存し、原本 PDF は `data/raw/tax-burden/oecd/` に版ごとに保管する。OECD の公開URLは「latest」が上書きされるため、参照は保管した版で固定する。R7 の制度基準日は R8 のモデル年の基準日に一致させる。
- 縦軸: **(所得税 + 住民税 + 社会保険料本人負担 − 児童手当等の現金給付) ÷ 世帯総年収**。年金・医療の受給、消費税・資産税、事業主負担は含まない。
- 日本の形: 年収300〜400万円台で負担率が急上昇し以降フラット。段差は「住民税非課税の外れ（平均比約70%≒360万円）」「ひとり親控除・児童手当所得制限の外れ」など。OECD主要国は低所得層への給付で負担率がマイナス〜なめらかに上昇。

## 3. ビュー設計（`/tax-burden`）

1つのページに **左サイドパネル（条件）＋ メイン（4つのビュータブ）** の構成。既存 `/mof-kou` 等と同じフィルタパネル部品を使う。

### 3.1 ビューA: 国の税・保険料収入ツリー

- **範囲**: 財務省予算書に載る収入のみ。一般会計の租税・印紙収入（款→項＝税目）と、年金特会・労働保険特会の **保険料収入**。画面上の名称は「国の予算上の税・保険料収入」とし、次を **含まない** ことを注記で明示する: 地方税（住民税・固定資産税等）、市町村国民健康保険・後期高齢者医療・介護保険の保険料、事業主負担と本人負担の区別。
- 表示: 款→項のサンキーまたは積み上げ棒。各税目ノードをクリックすると、ビューB/Cがその税目でハイライトされる。
- **指標の分離**: 次の3指標は分母・範囲が異なるため、別名で並記し混同させない。
  | 指標 | 分子 | 分母 | 出典 |
  |---|---|---|---|
  | 国の税・保険料収入 | 予算書の収入額 | （金額のみ、率は出さない） | 予算書歳入表 |
  | 国民負担率（財務省定義） | 国税＋地方税＋社会保障負担（事業主負担含む） | 国民所得 | 財務省公表値（年次、参考値として表示） |
  | 世帯負担率（ビューB/C） | 世帯が支払う税・保険料本人負担（− 給付） | 世帯年収 | 統計／シミュレーション |
- 地方税収は総務省「地方財政統計年報」の道府県税・市町村税の税目別 **決算額** を **参考値として並記** する（詳細ツリーは対象外、合計の1段のみ）。ビューAの国税は **予算額** であり性質が異なるため、**予算額の国税と決算額の地方税は合算しない**。
- **国・地方合計を出す条件**: 国税も決算額（財務省「租税及び印紙収入決算額調」）を R2 に取り込み、**同一年度の国税決算額と地方税決算額が両方公表されている年度に限り**「決算ベース 国・地方合計」を表示する。地方決算が未公表の年度は合計欄を「地方: 未公表」として空欄にし、予算額で代替しない。年度セレクタには各年度の「予算のみ／決算あり」を表示する。

### 3.2 ビューB: 階級別負担率（実態・統計集計）

- 横軸: 採用する統計表の **年収（所得）階級をそのまま**。縦軸: 年収に対する負担率、**税目別に積み上げ**（直接税＝所得税・住民税等、社会保険料、消費税（推計））。統計表が税目を分けていない場合は表の区分に従う。
- 切替軸: **表が持つ軸だけ** をサイドパネルで選べる。年収 × 年齢 × 世帯類型の **同時絞り込みは、それを持つクロス表が存在する場合のみ** 有効化し、無い組合せは選択肢を非活性にして理由（「この調査にこのクロス表は無い」）を表示する。Phase 0 で確定した表ID一覧（§5）以外の組合せは UI に出さない。
- **消費税推計**（家計調査・全国家計構造調査の支出額は **税込**）:
  - 負担額 ＝ Σ_品目（税込支出 × r/(1+r)）。標準税率 r=10%、軽減税率 r=8%、非課税（家賃、医療、学校教育費、保険料等）は 0。
  - 品目分類（収支項目分類の中分類・小分類）と課税区分の **対応表を手作成**（`public/data/tax-burden-consumption-map.json`、出典・判断理由付き）。外食を含む「食料」など標準・軽減が混在する項目は、可能な限り小分類で分け、分けられない項目は **按分比率を明記した推計** として扱い、対応表に `mixed` フラグと比率を持たせる。
  - 改革シミュレーション（ビューD）で税率を変える際は **「税抜の数量・価格を固定し、税込支出が税率変更分だけ動く」** を既定とし、注記に明示する（税込支出固定＝実質消費が減る仮定はトグルで選択可）。
- **「1億円の壁」サブビュー**: 国税庁 申告所得税標本調査の合計所得階級別に「所得税負担率」と所得構成（給与／事業／株式譲渡・配当）を重ねる。横軸は対数スケール。これは **統計の表示のみ** で、シミュレーションは行わない。
- 出典候補（全て e-Stat 公開集計表）:
  - 総務省 家計調査 年報（二人以上の世帯・勤労者世帯: 年間収入十分位／五分位 × 収支項目、世帯主年齢階級 × 収支項目。非消費支出＝直接税・社会保険料の内訳）
  - 総務省 全国家計構造調査 2019／2024（年間収入階級 × 世帯主年齢 × 収支項目、世帯類型 × 収支項目、単身世帯を含む）
  - 厚労省 国民生活基礎調査（所得階級 × 世帯類型、社会保険料の総所得比 × 世帯主年齢）
  - 国税庁 申告所得税標本調査／民間給与実態統計調査（所得階級別 税額・所得構成）
- 制約: いずれも **世帯単位の公開集計値**（マイクロデータではない）。調査ごとに階級・世帯類型の定義が異なるため統一しない。出典・調査年・推計方法をチャート下に必ず表示する。

### 3.3 ビューC: 翁カーブ（制度シミュレーション）

- 横軸: **世帯年収**（1万円〜2,000万円、連続。平均賃金比 % の副軸）。**年収0円は率が未定義** のため、カーブは1万円から描き、0円点は金額（給付額）のみをツールチップに表示する。縦軸: **純負担率 = (所得税 + 住民税 + 社会保険料本人負担 − 現金給付) ÷ 年収**。**負値を許容**（給付超過）。
- 系列: 世帯類型ごとに1本。既定は TaxBEN と同じ6類型（単身／片働き夫婦／共働き夫婦 × 子なし／子2人）。追加で **ひとり親＋子1**、**20代単身**、**40〜64歳単身（介護保険第2号）** を選択可能。
- **ビューCでは高齢夫婦（年金所得）を扱わない**。本モデルは正規被用者・給与所得のみを扱い、年金所得の課税（公的年金等控除）、後期高齢者医療・第1号介護保険料、夫婦間の年金額配分を持たないため、ビューCの選択肢に含めない。年金受給期を含む年齢軸は **別モデル（§3.6 ビューE）** で扱い、高齢者世帯の実測値はビューBで示す。
- **モデル適用範囲**: 固定条件「正規フルタイム被用者」が成立する **就労者1人あたり給与の下限** を、制度年の **最低賃金（全国加重平均）× 法定労働時間（40時間×52週）** とする。判定は **世帯年収ではなく、収入按分後の就労者ごと** に行い、世帯内に1人でも下限未満の就労者がいればその世帯年収点を「適用範囲外」とする（例: 共働き 67:33 では配偶者側が下限に達する世帯年収＝下限 ÷ 0.33 までが範囲外）。範囲外の点は薄色で描き、ツールチップに「配偶者の給与がフルタイム下限未満」など理由を出す。横軸を1万円から描くのは連続性のためであり、適用範囲外の値は検証・受入基準の対象にしない（§4.3）。
- **定型世帯の固定条件**（同じ年収でも結果が変わる要因をすべて固定し、画面の「計算条件」ダイアログに表示する）:
  | 項目 | 既定値 | 変更可否 |
  |---|---|---|
  | 制度年 | Phase 0 で確定した TaxBEN モデル年の制度基準日に合わせる（2025年版＝2025年1月1日は確認済、2024年版は基準日未確認）。確定後にもう1年分を同梱 | 年度セレクタ |
  | 就労形態 | 被用者・正規雇用、年間を通じて就労 | 固定 |
  | 加入保険 | 協会けんぽ（全国平均料率）・厚生年金・雇用保険（一般の事業）。40〜64歳は介護保険第2号 | 固定（年齢で介護のみ切替） |
  | 月給と賞与 | 年収を12等分、賞与なし（標準報酬月額表を月給で当てる） | トグル: 賞与2か月分 |
  | 居住地 | 東京都区部（住民税は標準税率、均等割は都区部の額） | 固定 |
  | 共働きの按分 | 67:33 | 変更可 |
  | 子の年齢 | 子2人は 3歳以上小学生（児童手当 月1万円区分）、ひとり親の子1人は同じ | 固定 |
  | 含める給付 | 児童手当（所得制限・特例給付は制度年に従う）、児童扶養手当（ひとり親のみ） | 固定 |
  | 含めない給付 | 生活保護、住宅手当、就学援助、年金・医療の受給 | 固定（注記） |
  | 控除 | 基礎控除、給与所得控除、社会保険料控除、配偶者（特別）控除、扶養控除、ひとり親控除。医療費・生命保険等は無し | 固定 |
- 積み上げ表示モード: 純負担率を **所得税／住民税／年金／医療・介護／雇用保険／−給付** に分解した面グラフ。段差点（住民税非課税の外れ、児童手当の所得制限、標準報酬上限、配偶者特別控除の逓減）に注記ラベルを付ける。
- **消費税を含む拡張モード**（翁カーブ本体との違いを明示するトグル）: ビューBの年収階級別の平均消費性向と課税区分別支出比率を使い、§3.2 の式で消費税負担率を推計・加算する。
- **OECD比較モード**: OECD tax-benefit calculator の公開結果（米・英・独・仏の同類型カーブ）を静的データとして同梱し重ね描き。
- 計算方式: 制度ルール（税率表、控除、標準報酬月額表、料率、給付の所得制限）を **年度別パラメータ JSON**（出典URL・基準日付き）として持ち、`app/lib/tax-burden/` の純粋関数で計算する。

### 3.4 ビューD: 「あるべき税」比較（制度改変シミュレーション）

- ビューCのカーブに対して、サイドパネルの **制度つまみ** を動かして「改革案カーブ」を破線で重ねる。つまみ候補（いずれも §3.3 のモデルで計算できるもの）:
  - 給付付き税額控除（対象所得帯、給付額、逓減率）
  - 基礎控除額・住民税非課税ライン
  - 児童手当の所得制限撤廃／額
  - 社会保険料率・標準報酬上限・低所得者への保険料減免
  - 消費税率（標準・軽減、§3.2 の固定仮定に従う）
- **スコープ外**: 金融所得課税の税率変更。§3.3 のモデルは給与所得のみで金融所得の種類・金額・課税方式を持たず、年収上限も2,000万円のため「1億円の壁への効果」は計算できない。1億円の壁はビューBの統計表示に限定する。
- **財政影響の表示**（世帯1件あたり）: 改革前後の差を **国税（所得税・消費税の国税分）差・地方税（住民税・地方消費税）差・保険料（年金／医療・介護／雇用）差・給付支出差** に分解して表示する。給付増は「歳入減」ではなく **歳出増** として符号と区分を分ける。
- **消費税差額の扱い**: 消費税率つまみを動かした場合、§3.2 の式で世帯の消費税負担差額を計算する。**固定仮定（税抜数量・価格固定／税込支出固定）は §3.2 のトグルで選択中の値を1か所の状態として共有し、カーブと財政影響は必ず同じ仮定で計算する**（URL クエリにも1キーで保存）。差額は**標準税率分は国 7.8／地方 2.2、軽減税率分は国 6.24／地方 1.76** の法定配分で国税・地方税の内訳に加える（地方消費税の都道府県間清算・市町村交付は区別せず「地方」に含める）。消費支出データが無い世帯類型（ビューBの表に対応する階級が無い場合）は、消費税の財政影響を **「未計算」と明示** し、ゼロとして合算しない。
- **財政影響の全国総額の表示条件**（すべて満たす場合のみ表示。満たさない場合は世帯1件あたりの差額のみ）:
  1. **重み**: 復元世帯数（全国推計用の重み）を持つ統計表がある（Phase 0 で確定）。
  2. **母集団の一致**: 重みの母集団を、モデルの前提（被用者・勤労者世帯、世帯主64歳以下、給与所得が主）に一致する区分に **絞り込める**（例: 勤労者世帯 × 世帯主年齢階級）。年金・事業所得世帯を含む区分は重みに使わない。
  3. **代表世帯への対応規則**: 統計の世帯類型 → 定型世帯の対応表（例: 「夫婦と子供2人・勤労者世帯」→ 共働き子2 と 片働き子2 を共働き率で按分）を `public/data/tax-burden-household-map.json` に持ち、子の人数・年齢、所得配分は代表値で固定したことを注記する。
  4. **カバー率の表示**: 「対象とした世帯数 ÷ 全世帯数」を総額と同じ場所に表示し、見出しを「**対象限定試算**（被用者世帯 xx% をカバー、行動変化なし）」とする。全世帯への外挿はしない。
  - 積算は「階級代表世帯の区分別差額 × 対応表で按分した復元世帯数」。合算値は範囲を明示した「財政収支への影響（国＋地方＋社会保険、対象限定）」とする。
- 改革案は URL クエリで共有できるようにする（§3.8）。

### 3.6 ビューE: 年齢軸（所得階層を固定し、年齢で負担率を追う。年金受給期を含む）

- **問い**: 同じ所得階層の人が、20歳から85歳まで各年齢で税・保険料をどれだけ払い、年金を受け取り始めるとどれだけ楽になるか。
- 横軸: **年齢 20〜85歳**（1歳刻み）。縦軸: **純負担率**（税＋本人保険料 − 現金給付）÷ その年齢の総収入（給与＋公的年金）。副表示として **可処分所得（総収入 − 純負担）** の折れ線も同じ図に出せるようにする（「楽になる」は負担率の低下と手取りの両方で読むため）。
- 固定するもの: **所得階層**（現役期の年収。ビューCと同じ年収スライダー、または年収十分位の代表値）と世帯類型（ビューCの6類型）。
- **ライフステージの区分と収入の定義**（すべて画面の「計算条件」に表示し、各境界年齢はパラメータ化する）:
  | 年齢 | 収入 | 加入制度 |
  |---|---|---|
  | 20〜59 | 固定した年収（給与） | 厚生年金・協会けんぽ・雇用保険。40〜64歳は介護第2号 |
  | 60〜64 | 給与 × 継続雇用係数（既定 0.7、変更可）。年金なし（65歳支給開始を既定、60〜64繰上げは対象外） | 同上 |
  | 65〜74 | **公的年金のみ**（既定）。トグルで「65〜69歳は就労継続＋年金」も選択可（在職老齢年金の支給停止を適用） | 国民健康保険（東京都区部の料率・均等割・賦課限度額）、介護第1号（所得段階別定額、区部の例示自治体を固定） |
  | 75〜85 | 公的年金のみ | 後期高齢者医療（東京都広域連合の料率）、介護第1号 |
- **年金額モデル**: 老齢基礎年金（満額、加入40年）＋老齢厚生年金（報酬比例部分 ＝ 平均標準報酬額 × 5.481/1000 × 加入月数。平均標準報酬額は固定した年収から求めた標準報酬月額（上限あり）＋賞与を用い、加入期間は 20〜59歳の480か月を既定）。片働き夫婦の配偶者は基礎年金のみ（第3号）。共働きは各自の給与で計算。加給年金・経過的加算・繰下げは対象外と明示。
- **年金所得の課税**: 雑所得（公的年金等控除、65歳未満／以上の区分）、所得税・住民税は現役と同じ税率表。年金からの特別徴収は無視（年額で計算）。
- **給付の扱い**: 年金は「収入」であって「現金給付」ではないため純負担率の分子に入れない。年金生活者支援給付金は現金給付として分子から引く（所得要件を適用）。
- **段差の注記**: 40歳（介護第2号）、60歳（継続雇用）、65歳（年金開始・公的年金等控除・国保／第1号介護）、75歳（後期高齢者医療）を縦線で示す。
- **受入基準**: 厚労省が毎年度公表する「モデル年金」（平均的な収入で40年就業した夫婦の年金月額）を、同じ前提（平均標準報酬額）で入力したときに **±1%以内** で再現する。国保・後期高齢者医療・第1号介護の保険料は、固定した自治体の公表計算例と **±1,000円以内** で一致する。
- ビューCと同じく、制度年・自治体・係数はパラメータ JSON（R11）に持ち、`app/lib/tax-burden/simulate-lifecycle.ts`（純粋関数）で計算する。ビューCの `simulate.ts` を現役期の計算に再利用する。

### 3.7 ビューF: 税目別「誰が払っているか」ヒートマップ（年齢階級 × 所得階級）

- **問い**: 所得税・住民税・年金保険料・健康保険料・介護保険料・消費税のそれぞれは、どの年齢層・どの所得階層に重いか。
- 表示: 税目を1つ選び、**行＝世帯主年齢階級、列＝年収階級** のヒートマップ。セルの値は2モードで切り替える。
  1. **負担率モード**: その階級の年収に対する当該税目の負担率（%）。「重さ」を見る。
  2. **分布モード**: 当該税目の総額に占めるその階級のシェア（%）。「誰が払っているか」を見る。**復元世帯数が使える表に限り有効化**（§3.4 と同じ条件）。
- 税目のタブを横に並べ、同じ階級セルを税目間で比較できるようにする（所得税は右上に濃く、消費税は左下に濃く、保険料は中央帯が濃い、という違いが並べて読める）。ビューAの税目ノードからこのビューへ遷移する。
- **データ源（統計ベースを既定）**: 全国家計構造調査の「世帯主の年齢階級 × 年間収入階級 × 収支項目（中分類）」クロス表（二人以上の世帯・勤労者世帯、および単身世帯）。非消費支出の中分類に **勤労所得税・個人住民税・他の税・公的年金保険料・健康保険料・介護保険料・他の社会保険料** が分かれているため、これらはそのまま税目セルになる。**消費税**は同表の消費支出中分類から §3.2 の式で推計（中分類では標準・軽減の分離が粗いため、混在項目の按分を R9 に明記）。酒税・たばこ税・揮発油税は「酒類」「たばこ」「自動車等関係費（ガソリン）」の支出に税率を掛けた推計として **推計マーク付き** で追加する。
- **モデルベースの補助表示**: ビューC・Eの計算式で同じ年齢 × 年収グリッドを描く「制度上の負担率」を切り替えで並べ、統計の実測値との差（未申告・非正規・自営業・年金受給の混在）を読めるようにする。
- 空セル（表に該当階級が無い、または標本世帯数が公表基準未満で秘匿）は空白にし、補完しない。
- 表示条件: Phase 0 で当該クロス表の表ID・階級・母集団・復元世帯数を確認できた組合せに限る。

### 3.8 状態の保存と URL 共有

- **URL クエリ**（共有対象）: ビュー、制度年、世帯類型、按分、つまみ値、**消費税の固定仮定（カーブと財政影響で共有する1キー）**、表示モード。`app/project-bubble/page.tsx` と同じく `URLSearchParams` で読み、`history.replaceState` で書き戻す。シリアライズは `app/lib/tax-burden/reform-url.ts`（純粋関数）に置き、**モデルバージョン `v` と制度年 `fy` を必須キー** にする。バージョン不一致の URL は既定値にフォールバックし、その旨を表示する。
- **localStorage**（個人設定のみ、共有しない）: 最後に開いたビュー、注記の折りたたみ状態など。`usePersistedState` を使う。
- **優先順位**: URL クエリ ＞ localStorage ＞ 既定値。URL にキーがあればそのビューでは localStorage を読まない。

### 4.2 生成スクリプト（`scripts/`、CSV処理のみ）

- `scripts/generate-tax-revenue-data.ts`: R1 の歳入表を款→項（税目）まで集計し、年金・労働保険特会の保険料収入を合わせて `public/data/tax-revenue-{年度}.json` を出力。既存 `mof-budget-csv.ts` を再利用。R2 を同梱。
- `scripts/generate-tax-burden-stats.ts`: R3〜R6 を **調査ごと・表ごとに正規化**（表ID、軸の種類、階級ラベル、世帯類型、年齢階級、税目コード、**復元世帯数の有無**）し `public/data/tax-burden-stats-{調査}-{年}.json` を出力。消費税推計はここでは行わず、収支項目別の税込支出額を保持するだけ（推計はドメインロジック側）。
- `scripts/validate-tax-burden-data.ts`: 検証規則は **指標別**（§4.3）。加えて款合計＝既存 `mof-budget-overview` の租税額と一致、階級の欠損、対応表の品目網羅（統計の全収支項目が対応表に載っている）を確認する。
- R7・R8・R9 は手作成・レビュー対象（`validate` でスキーマ検証のみ）。
- `package.json`: `generate-tax-burden-data`, `validate-tax-burden-data` を追加し、`compress-data` に `tax-revenue-*.json`, `tax-burden-*.json` のグロブを追加。API経由配信のため `decompress-data.sh` は触らない。

### 4.3 ドメインロジック（`app/lib/tax-burden/`、HTTP・React禁止）

- `simulate.ts`: §3.3 の固定条件を含む定型世帯定義と制度年パラメータを受け取り、年収の各点で所得税・住民税・年金・医療・介護・雇用保険・現金給付を **金額** で返す純粋関数。率への変換は呼び出し側（年収0では率を返さない）。ブラウザ側からも直接 import する。
- `consumption-tax.ts`: §3.2 の式（税込 × r/(1+r)、対応表、混在按分、改革時の固定仮定）。
- `fiscal-impact.ts`: 改革前後の差を国税・地方税・保険料・給付の区分別に返す（消費税差額は §3.4 の法定配分で国・地方に振り分け、消費データが無い場合は `uncomputed` を返す）。総額は §3.4 の4条件を満たす入力（重み・母集団区分・R10 対応表）が揃った場合のみ計算し、カバー率と範囲ラベルを結果に含める。
- `stats-shaping.ts`: 正規化データから、選択された表と軸でチャート用の系列を組み立てる。存在しない軸の組合せは選択肢として返さない。
- `reform-url.ts`: 改革案・表示条件のシリアライズ／復元（§3.8）。
- **指標別の検証規則**（`validate` とランタイム両方で使う）:
  | 指標 | 規則 |
  |---|---|
  | 税・保険料の各金額 | 0以上 |
  | 現金給付の金額 | 0以上 |
  | 純負担率（÷年収） | 年収>0 のときのみ定義。**上下限なし**（給付超過で負、低年収では保険料だけで100%超になり得る）。値域チェックはせず、適用範囲フラグで扱う |
  | 総負担率（÷年収、給付を引かない） | 0以上、上限なし |
  | 消費税負担額 ÷ 課税対象の税込支出 | **支出比で検証**: 0以上、**その計算に使用した標準・軽減税率の大きい方 r_max に対する r_max/(1+r_max) 以下**（既定 10% なら 10/110、改革案 20% なら 20/120 と動的に算出する。固定値は持たない）。年収比には上限を置かない（年収100万円・課税支出220万円なら年収比20%は正しい） |
  | モデル適用範囲 | §3.3 に従い、収入按分後の就労者のうち1人でも給与が下限（最低賃金フルタイム年収）未満なら、世帯の計算結果に `outOfScope` を付ける。非就労の配偶者は判定対象外とする。フラグ付きの点は受入基準・値域検証の対象外、表示は薄色 |
  | 統計の負担率 | 表の値どおり。0〜100% を外れる場合は出典側の定義を確認しフラグを付ける |

### 4.4 API（`app/api/tax-burden/`）

- `revenue/route.ts`（年度 → 税目別収入）、`stats/route.ts`（調査・年 → 正規化集計、表IDと利用可能軸の一覧を含む）、`params/route.ts`（制度年 → パラメータ）、`oecd/route.ts`。全て `readDataJson()` で読み、`API_CACHE_CONTROL` を付ける。ロジックは `app/lib/tax-burden/` に委譲。

### 4.5 型（`types/tax-burden.ts`）

- 税目コード、世帯類型、年齢階級、調査ID／表ID、軸の種類、階級区分、復元世帯数、制度パラメータ、定型世帯の固定条件、シミュレーション結果（金額）、財政影響（区分別）、改革案（URLシリアライズ可能、`v`・`fy` 必須）。

## 5. 実装フェーズ

### Phase 0（先行確認。コードより先に完了させる）

1. **統計表の確定**: R3〜R6 について、採用する e-Stat 表ID、軸（年収階級／年齢／世帯類型のどれを同時に持つか）、母集団（二人以上／単身／勤労者）、**復元世帯数の有無** を一覧表にして `docs/tasks/` に記録する。UI で選べる組合せはこの一覧に限定する。
2. **翁カーブ資料の照合**: 国民会議 資料11（PDF）と NIRA No.89 を目視で確認し、横軸の定義（世帯年収か平均賃金比か）、6類型の定義、給付の範囲を §2.3 と突き合わせて差異を記録する。
3. **制度基準日の確定**: OECD 日本 2024年版・2025年版の原本を取得・保管し、各版の制度基準日と資料改訂日を記録する（2025年版＝2025年1月1日は確認済、2024年版は未確認）。R7 の制度年をどちらに合わせるか決める。
4. **参照値の取得**: OECD tax-benefit calculator で日本・6類型・確定した制度年の出力（税目別金額）を平均賃金比 50〜200% の各点で取得し R8 として保存する。
5. **品目対応表・世帯対応表の作成**: R9（課税区分）と R10（統計世帯類型→定型世帯）を作り、判断根拠と按分率の出典を記録する。
6. **重みの母集団確認**: 復元世帯数を持つ表について、勤労者世帯・世帯主年齢で絞り込めるか、対象カバー率がいくらになるかを記録し、§3.4 の総額表示が成立する組合せを一覧にする。

### Phase 1（翁カーブ再現）

  2. 段差の位置検証: 住民税非課税ライン、児童手当の所得制限・上限、標準報酬月額の上限、配偶者特別控除の逓減開始・終了について、閾値の **前後1万円** の年収で計算し、金額の変化が制度どおりの方向・大きさで生じる。
  3. 純負担率の負値と年収0の扱いが §3.3・§4.3 に従う。
  4. 差異が基準を超える項目は、原因（TaxBEN の仮定との差）を注記に記載しない限り合格としない。

## 6. リスク・未確定事項

- **高齢期の保険料の自治体差**: 国保・介護第1号は市区町村ごとに料率・段階が異なる。固定自治体（東京都区部の1区）を明示し、全国代表値と称さない。
- **年金額モデルの単純化**: 加入40年・同一年収の前提は実際の賃金カーブと異なる。「同じ所得階層に生涯いた場合」の仮定として画面に明示する。
- **ヒートマップの母集団混在**: 統計の年齢 × 年収セルには自営業・非正規・年金受給世帯が混ざるため、制度モデルの値と一致しない。差はモデル補助表示で見せ、補正はしない。

- **翁カーブの再現精度**: TaxBEN 日本モデルの細部（住宅手当・生活保護の扱い、住民税の課税年度ズレ）は OECD 説明書で確認するが、資料11 の図とは横軸定義が異なる可能性がある。Phase 0 で確認し、差異は注記する。
- **消費税の推計**: 混在品目の按分比率と、貯蓄・耐久財の扱いで数ポイント動く。対応表と仮定を固定し注記する。
- **統計の階級不一致とクロス表の不足**: 年収 × 年齢 × 世帯類型を同時に持つ公開表が無い可能性が高い。無い組合せは UI に出さない。
- **全国推計の重み**: 家計調査の公開表には復元世帯数が無い。全国家計構造調査・国民生活基礎調査の推計世帯数で代替できるかは Phase 0 で確定する。確保できない場合、財政影響の総額は表示しない。
- **社会保険料の範囲**: 既定は本人負担のみ（翁カーブと同一）。事業主負担込みはトグルで表示可能にするが、財務省の国民負担率とは分母が異なるため同一チャートに重ねない。
- **財政影響の性質**: 行動変化なし・世帯集計ベース・定型世帯の代表値による概算であることを画面上で明示する。
- **国の収入と世帯負担の突合**: 消費税は家計以外の負担分があるため、ビューAの金額とビューBの負担額は突合せず、比率として見せる。
