# 歳入・国民負担可視化：Phase 0 確認記録

確認日: 2026-09-13。設計書の Phase 0 は未完了。以下は取得・照合できた範囲と、公開前の残作業を区別した記録。

## 一次資料の確認

- [OECD Japan 2025](https://www.oecd.org/content/dam/oecd/en/topics/policy-sub-issues/income-support-redistribution-and-work-incentives/TaxBEN-Japan-latest.pdf) を Web 経由で閲覧。表紙は2025年版、資料改訂は2025年11月、p.4の制度基準日は2025-01-01。本文には2025年の所得税改正も含まれる。暦年の納税額そのものとの一致は別途検証が必要。
- 2024年版の推測URLは取得できなかった。2024年のパラメータを2025年から推測して補完しない。
- 原本PDFのローカル取得は環境のネットワーク制約（WinError 10013）により未実施。原本ファイルのSHA-256は未取得。Web本文のハッシュを原本のハッシュとして扱わない。
- 設計記載の[国民会議資料11](https://www.cas.go.jp/jp/seisaku/kokuminkaigi/contents/20260324/11_siryou11.pdf) はWeb取得で404。正式な資料URLの再特定が必要。
- [NIRA No.89](https://www.nira.or.jp/paper/opinion-paper/2026/89.html) 本文の図注は閲覧できた。2024年TaxBENを基に日本の2025・2026年度改正を反映、日本の大人40歳・子2歳と6歳、横軸の平均年収540万円。**図によって所得条件が異なる**。図1・2は第2稼ぎ手の年収142万円を固定（賃金率35%・労働時間75%）、主要4カ国比較では夫婦所得50:50に変更している。前の記録の「夫婦所得50:50」は全図共通の条件ではなかった。設計の67:33・小学生2人・単一制度年とは一致しない。独自実装をこの図の再現済みと称さない。
- [OECD calculator](https://taxben.oecd.org/) は選択フォームまで閲覧できた。6世帯×所得点の計算結果・税目別参照金額（R8）は未取得。原資料説明書から自作した値をR8に転用しない。

## Playwrightでの再調査（2026-09-13）

- 実際に `@playwright/test` の Chromium を起動し、OECD calculator と国民会議資料11へ `page.goto` した。両URLとも `net::ERR_NETWORK_ACCESS_DENIED`。HTTP応答より前の通信拒否であり、待ち時間やセレクタの調整で解決する失敗ではない。ブラウザは起動できるが、現在の実行環境では外部サイトを操作できない。
- 再現コマンドは `node scripts/probe-taxben-browser.mjs`。成功時にはHTML・本文・スクリーンショット、失敗時にはURL・requestfailed・例外を `test-results/taxben-research/` に保存する。アクセスできない場合は終了コード1。計算結果の取得や照合を成功扱いしない。
- 利用可能なWeb閲覧ツールでは資料11のURLが再び404となった。ただし同一URLを掲載した紹介記事は検索できたため、「URLが誤記」「資料が恒久的に削除された」とまでは断定できない。Playwright側では404自体を確認できていない。
- NIRA公式記事の「全文を読む（2026年5月28日更新）」から [No.89 PDF（10ページ）](https://www.nira.or.jp/paper/opinion89.pdf) に到達し、Web経由で本文を閲覧できた。これは国民会議資料11そのものではない。原本バイナリのローカル保存・SHA-256取得は未完了。
- [OECD calculator](https://taxben.oecd.org/) のWeb本文には結果のXLSXダウンロードとログ表示がある。入力フォームの閲覧は計算実行・出力取得の証拠にならない。R8取得・税目別照合は引き続き未完了。

再開には外部通信可能なPlaywright実行環境が必要。そこでまず実DOMと日本の選択可能年を確認し、入力条件・モデル版・計算ログ・ダウンロードXLSXを一緒に保存する。取得前に推測のセレクタやAPIで照合済みデータを作らない。

## 既存データ

`public/data/mof-budget-overview-{2017..2026}.json.gz` は利用可能。実ファイルの調査で、`generalAccount.revenue.taxes` に税目別内訳がすでに収録されていることを確認した（設計書の未収録という記述とは異なる）。元の予算書 ZIP は現在のワークスペースには無い。一般会計の租税・印紙収入は既存の圧縮データから再利用する。ローカルの2023年raw JSONは旧スキーマなので、生成元はGit管理される`.gz`に固定する。特別会計の「保険収入」款は国庫からの受入を含む可能性があるため、そのまま保険料収入にしない。

## 受入前に必要な確認

1. PDF原本を保存して取得元・改訂日・SHA-256を確定。
2. OECD実出力を取得し、採用する固定条件との違いを確認した上で税目別に照合。
3. 統計の実数値・単位・母集団・分類の重複を確認してR3〜R6の採用表を確定。
4. R9・R10と対象世帯数を確定。全条件が揃うまで全国総額は提供しない。
5. 2025年資料内の料率・控除の記載差、住民税の対象所得年・調整控除、端数処理を原制度資料と照合。
