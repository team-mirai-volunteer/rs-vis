# レスポンシブ対応とチームみらいデザインシステムの再適用

## 現状（2026-09-14 調査）

### デザインシステム（.claude/skills/mirai-design §10 の grep）

| チェック | 件数 | 判定 |
|---|---|---|
| `text-[#xxx]` 等の arbitrary hex クラス | 0 | ✅ |
| cool gray パレット（slate/zinc/gray/stone） | 0 | ✅ |
| `shadow-lg` 以上 | 0（コメントのみ） | ✅ |
| `transition-all` / `backdrop-blur` / `font-light` | 0 | ✅ |
| 生 `<button>` | 0（`components/ui/button.tsx` の実装のみ） | ✅ |
| インライン style の色 | 32 | ほぼデータ色（府省庁色・ブロック種別・MOF 予算種別）。chrome 色の hex 直書きが再委託ページのブロック図に数か所（`#475569` `#64748b` `#fff`）と統合ビューの繰入ストローク `#64748b` |

→ トークン適用は済んでいる。残りは chrome 色の hex をトークン（`var(--mirai-text-secondary)` 等）へ置き換えるだけ。

### レスポンシブ（幅 390px で撮影）

| ページ | 問題 |
|---|---|
| 共通ヘッダー | 右スロット（基準・プリセット・年度・事業/項）が島から溢れ、ハンバーガーが切れる（サンキー図・評価一覧） |
| サンキー図 | 表示数のカード 2 枚が縦に積まれて検索ボックスを覆う。サイドパネル（幅 400）が画面を埋める |
| バブルチャート | 左フロート列（268px）と右の凡例（288px）が重なり、図がほぼ見えない |
| 評価一覧 | ヘッダーの絞り込み群（ヒストグラム・検索・セレクト・範囲入力）が中央に浮いて崩れる。表は横スクロールで OK |
| 委託構造 一覧 | 概ね OK（表は横スクロール） |
| 委託構造 詳細 | サイドパネルが図を全部覆う |
| トップ・歳入 | OK |

横スクロール（scrollWidth > innerWidth）はどのページにも無い。

## 方針

スマホは「読む・探す」が主で、細かい操作（TopN・幅リサイズ・列トグル）は PC 前提のままでよい。
共通部品を直せば大半が片づくので、共通 → ページ固有の順で当てる。ブレークポイントは Tailwind の `sm`（640px）1 本。

1. **AppHeader**: 640px 未満では右スロットを 2 段目に落とし、横スクロールできる列にする（`flex-wrap` + `basis-full`）。
   `--app-header-h` を 640px 未満で 118px にし、固定キャンバス型ページはそのまま追従させる
2. **SidePanelChrome**: 640px 未満ではボトムシート（左右下 12px、高さ 52vh、リサイズ無し）。
   サンキー図・委託構造詳細の両方に効く。図のフィット計算はパネル幅を 0 として扱う
3. **useMediaQuery フック**（`client/hooks/useMediaQuery.ts`）を共通化。SSR では false
4. **サンキー図**: 640px 未満では表示数カードと設定を右上の 1 ボタンに畳み、押すと下に開く
5. **バブルチャート**: 640px 未満では左列を全幅・上部に、凡例は非表示（表ビューで代替）
6. **評価一覧**: 640px 未満では絞り込み群を「絞り込み」ボタンで開閉する
7. **色の hex 残り**: 再委託詳細のブロック図と統合ビューの繰入ストロークをトークンへ

## 進め方

1〜3 と 7 を先に 1 コミット、4〜6 をページごとに 1 コミットずつ。各コミットで 390px と 1440px のスクリーンショットを撮って確認する。
