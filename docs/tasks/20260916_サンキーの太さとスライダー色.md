# サンキーの太さとスライダー色

## 金額の太さ

旧サンキーでも `7c82d19` と `c9df82b` で縦方向の表示領域を拡大していた。統合ビューではラベル用の行間を画面高から引いて帯を縮めており、2024年度・1440×1000の初期表示で264ノード中192個が最低表示の1pxに潰れていた。

金額に使う高さと行間を分離し、行間は図の高さに追加する。初期倍率は旧図と同じ1.25倍。修正後、同じ条件で1pxのノードは38個。金額を線形に描くため、極端に小さい金額は依然1pxになる。

表示設定に「帯・ノードの太さ」（0.25〜8倍、0.25刻み）を追加。横幅・文字サイズ・金額自体は変えず、ノードと帯の高さに同じ倍率を使う。はみ出しはパンで表示する。`th` パラメータで共有・再読み込み・履歴から復元でき、初期値へ戻す操作も設けた。

単体テストは密なグラフで金額比・帯とノードの整合・フォント変更からの独立を検証。ブラウザテストは太さ変更・共有URL・リセット・ズーム・文字サイズを検証する。

## スライダー全実装の確認

`app`・`client`・`components` の全 `input[type=range]` と `role=slider` を検索した。

- 単一つまみ：税負担、財政余力、フォントサイズ、表示件数、階層図の開始位置、項×RSの開始位置、委託詳細の縦ズーム、新設の太さ。すべて共通 `policy-range`（薄灰色のバー・緑のつまみ）を使用。
- 上下限の2つまみ：項・事項・項目の一覧が共有する `RangeSlider`。バーは薄灰色、選択区間は濃い灰色、つまみは緑。重ねたinputの軌道は透明を維持する。
- 表示範囲のスクロール型：`RangeWindowRow`。灰色の軌道を共通トークンに統一し、範囲文字を読める薄緑のハンドルを維持する。

縦ズームは縦用の軌道寸法を指定し、横のスライダーと同じ6px幅にする。実画面で単一・上下限・縦スライダーの表示とキーボード操作、モバイルの太さ操作を確認した。

関連ブラウザ検証で、表示件数コントロールの空白領域が詳細パネルの閉じるボタンを遮る問題も検出。空白領域はクリックを通し、カードと設定ボタンだけが受け取るよう修正した。

型チェック・単体10件・関連ブラウザ23件が成功。ブラウザ検証は統合サンキー20件と税負担3件。共通スライダーの実表示は財政余力、階層図、項×RS、項・事項・項目一覧、委託詳細でも確認した。
