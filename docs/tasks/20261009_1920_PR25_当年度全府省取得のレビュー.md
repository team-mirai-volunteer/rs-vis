## コードの確認

- **年度判定の厳格化**（`budget-requests-discover.ts`）: URL の年度マーカーを「実証された書式」（ファイル名の r9_/h31_、fy2027、gaisan/soshiki/policies/budget の r9、r9yokyu など）に限定し、MEXT/環境省の CMS フォルダ名（r01）やデジタル庁の公開年、日付 8 桁を年度とみなさない。見出しの階層（h1〜h6 と、水産庁のような段落の年度ラベル）を積み、リンク自身の明示年度 → 行 → 見出しの順で判定。複数年度が混在するページでは年度の根拠がないリンクを取らない。妥当
- **範囲外の整理**（`budget-requests-scope.ts`）: 保存済み HTML を再解析し、現在の規則で「明示的に除外された」リンクだけを除く。見つからないだけのリンクは消さない。根（財務省索引）は府省側の判定で消さない。原本は削除しない。妥当
- **取得失敗時の続行**: 掲載ページが取れなくてもハッシュ検証済みの保存 HTML から当年度リンクをたどり、ページ自体は fetch_failed のまま注記を残す。妥当
- **歳入の二重ガード**: 抽出器側でも歳入資料を弾く。妥当
- **探索深度 3 を既定に**し、日次継続の判定も 3 に揃えた。チェックポイントの fingerprint に scope.ts を含めたので、旧チェックポイントは自動で無効になる
- `mainContent()` が MAFF の `contentsBody` 等の div をバランスした閉じタグまで切り出し、コメント・aside を除去。回帰テスト（discovery-scope 等）あり

## 指摘

### 中 1. 40MB 超の 5 本は自動更新で毎週 fetch_failed になる（`scripts/fetch-budget-requests.ts` `MAX_BYTES`）

今回は手元で 400MiB まで許して保存した（合計 665MB、国交省の一般会計など）。ワークフローの上限は 40MB のままなので、週次の再取得では「40 MB を超える資料は未取得」で fetch_failed になり、UI では「記録時の取得に失敗。以下は過去の取得時点の記録です」の警告が国交省の主要な表に毎週つく。`MAX_BYTES` を環境変数で上書きできるようにし（例: `BUDGET_REQUEST_MAX_BYTES`、ワークフローでは 512MB）、メモリに乗せる前に Content-Length で判定する今の作りを維持すれば足りる。pdfjs の処理メモリは手元で通っているので runner（7GB）でも問題ない見込み。

### 中 2. 403 の 3 公開元（経産省・法務省・公取委）

同じ URL をブラウザでは開けるので、WAF が非ブラウザの User-Agent を弾いている可能性が高い（経産省は当方の curl でも 403）。選択肢は (a) このまま「取得失敗」として残す（現状）、(b) Accept-Language 等を足して一般的なブラウザ UA に寄せる、(c) 手動取得した原本をキャッシュに置いて `--resume` で取り込む。(b) は相手サイトの意思に反する可能性があるので、まずは現状維持で、カバレッジの注記に「3 府省は公開元の設定により自動取得できない」と明記するのがよい。

### 低 3. Windows でローダーのテストが落ちる（修正を push 済み）

`tests/budget-requests-loader.test.ts` が `--import` に `require.resolve('tsx')` の Windows パスを渡していて、ESM ローダーが `c:` スキームを拒否する。`pathToFileURL(...).href` に直した（CI は Linux なので影響なし）。

### 低 4. 内閣府 29.pdf の単位未検出

2 ページ目に「単位」の宣言が無いか位置が違うため 5 行が確定しない。同じ資料の 1 ページ目に宣言があるなら、資料内で最初に見つけた単位を以後のページに引き継ぐ現在の実装で拾えるはずなので、1 ページ目が「未対応レイアウト」としてスキップされた際に単位だけは読む、という改善で直る。
